## 1. 被测实现

### 1.1 退款主流程（refundSaleOrder）

前置检查（任一不满足抛 `UserInputError`）：

1. 出售单存在且属于当前渠道（`channelId` 过滤，无本人归属校验）
2. `payMode ≠ 'ORDER_SURCHARGE'`（加价购退款走主订单）
3. `status = 'PAID'`
4. `isSaleOrderRefundable`：出售单下**所有券状态 ≠ USED**（已核销不可退）
5. `CouponBalancePort` 已注册（余额返还通道可用）

事务内动作（原子性保障）：

- **状态机原子更新**：`UPDATE coupon_sale_order SET status='REFUNDED', refundedAt=now() WHERE id=:id AND status='PAID'` —— 带原状态条件，并发下 `affected=0` 即拒绝（防双退）
- **券批量作废** `invalidateCoupons`
- **余额返还** `port.addBalance(customerId, amount)`

### 1.2 退款联动（onSaleOrderRefunded，commit 后触发）

| 结算单状态 | 联动动作 | 目标状态 |
|---|---|---|
| PENDING（未分账） | 取消登记（原子更新带原状态条件，备注退款原因） | CANCELLED |
| SETTLED / PAID_OUT（已分账） | 调用 `adapter.refundSplit` 追偿 → 成功后落 `reversedAt` + 追偿回执号备注 | REVERSED |

**容错设计**：联动失败只记日志、不阻断退款主流程；漏网结算单由 T5 三方对账兜底发现。

## 2. 验证设计与真/假边界

### 2.1 核心洞察：竞争窗口模拟

真实时序下「核销 → 券 USED → 不可退」，`isSaleOrderRefundable` 会拒绝退款 —— 而**结算单只在核销时登记**，两者天然互斥。T8 联动的实际触发面是「先核销后退款」的**竞争窗口**。因此验证脚本采用：

- **[假] SQL 注入**：直接插入 PAID 出售单 + UNUSED 券 + 已核销流水（`in_store_bill`，billedAt=昨日），跳过支付与核销 API，人为制造「有结算待联动但券仍可退」的窗口态
- **[真] 全真 API 链**：退款走 `admin-api refundCouponSaleOrder` mutation，状态机/券作废/余额返还/联动与线上一致；结算推进走 `runCouponSettlementCycle`（补登 → T+1 提交 → stub 回执推进）

> admin 端调用等价性论证：service 层仅按 `channelId` 过滤、无 customerId 归属校验，admin 调用与 shop 调用走同一 service 全链，行为完全一致。

### 2.2 数据卫生设计

- 测试数据全量打标：`remark='T8VFY-*'` / `code LIKE 'T8VFY-%'` / `settlementNo LIKE 'T8VFY-%'`
- 金额 1 分：退款返还余额残留无害化
- 脚本幂等：执行前先清理同前缀残留，可安全重跑

## 4. 单测层验证（coupon-settlement.service.spec.ts，c21bced98）

`onSaleOrderRefunded` describe 块 6 用例：

1. **无结算单** → 空跑 `0/0/0` 不抛错
2. **PENDING → CANCELLED**：原子更新带原状态条件 + 备注退款原因
3. **PAID_OUT → 追偿受理 → REVERSED**：带原状态集合条件 + 追偿回执备注落值
4. **追偿被拒** → `failed` 计数、状态不更新（留在重试/对账兜底）
5. **原子更新未命中**（并发已变状态）→ 不计 `cancelled`（不误报，对账兜底）
6. **查询异常** → 不抛错、全量计 `failed`（退款主流程不被阻断）

## 5. 调试记录（脚本开发过程中的 4 个问题）

| 问题 | 根因 | 修复 |

## 7. 风险与限制

1. **竞争窗口模拟的边界**：注入方式跳过了支付/核销 API 层（这两层各有独立验证覆盖），但保证了退款→联动全链真实
2. **stub 分账**：追偿为 stub 回执（`STUB-REV-*`），微信实联追偿待合规前置（商户进件 + Q3.1/Q3.2 书面结论）后按同接口接入
3. **退款入口权限**：admin-api 与 shop-api 均可触发退款，生产运营以 web-admin 出售单页操作为主

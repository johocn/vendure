## 一、背景与问题

阶段3实现拆单履约后，一个订单行可能从多个仓库实际发货（如 A仓 5 件、B仓 3 件）。当前售后退货回补逻辑（`after-sales-plugin` 的 `confirmReceive`）把退货数量**全额回补到单一主仓**（`orderLine.stockLocationId`），导致：

- 拆单订单退货后，回补的库存位置不准确（本应回 A仓的货回到了 B仓）
- `afterSales:in` 账本只有一条，无法按仓追溯
- 各仓实际库存与账本失真，长期累积会造成库存水位偏差

## 二、目标与成功标准

**目标**：拆单订单发生售后退货（`Received`）时，按**各仓实际发货比例**回补库存，逐仓写 `afterSales:in` 账本，并在售后单上留痕回补明细。

**成功标准**：
1. 拆单双仓发货（A 5 / B 3）后，退货 4 件 → A仓 +3、B仓 +1（按最大余数法整数分配，Σ=4）
2. 库存账本出现两条 `afterSales:in`，`stockLocationId` 精确到各仓
3. `AfterSalesRequest` 记录 `restockJson`（各仓回补明细），后台可查
4. 单仓订单行为不变（退货仍回原仓）
5. 全额退货 → 各仓回补量 = 各仓实际发货量
6. 阶段2/3 全部回归测试通过

## 三、非目标（边界）

- 本期不做前端展示（回补为后台操作，售后详情展示各仓回补可后续迭代）
- 不做真实配送平台对接、不做 `OrderPackage` 实体持久化（阶段3其余边界项，另行立项）

## 四、架构与组件

### 4.1 inventory-plugin：新增 `applyAfterSalesRestockMulti` 服务方法

文件：`packages/inventory-plugin/src/inventory.service.ts`

```
applyAfterSalesRestockMulti(ctx, orderLineId, quantity, afterSalesCode)
    → Promise<Array<{ stockLocationId, quantity }>>
```

内部逻辑：
1. 查询该 orderLine 的 `Sale` 记录，按 `stockLocation` 分组求和（取绝对值）→ 各仓实际发货量
2. 仅单一仓 → 退化为现有 `applyAfterSalesRestock` 单仓逻辑（回补该仓）
3. 多仓 → 按发货比例用**最大余数法**整数分配回补量到各仓
4. 逐仓调用现有 `adjustStockForLocation`（同一事务，写 `afterSales:in` 账本，`bizCode = AS<id>`）
5. 返回各仓回补明细 `[{ stockLocationId, quantity }]`
6. 兜底：查不到 `Sale`（防御性）→ 回退 `orderLine.stockLocationId` 单仓（现状行为）

### 4.2 after-sales-plugin：`confirmReceive` 委托多仓回补

文件：`packages/after-sales-plugin/src/after-sales.service.ts`

1. `confirmReceive` 计算 `recoverQty = min(orderedQty, receivedQuantity ?? orderedQty)`
2. 委托调用 `applyAfterSalesRestockMulti(orderLineId, recoverQty, AS<id>)`
3. 新增 `AfterSalesRequest` 实体列 `restockJson`（JSON 文本），记录 `[{ stockLocationId, quantity }]`
4. 保留现有 try/catch：回补失败仅告警，**不阻断**收退货/退款流程

## 五、数据流

```
confirmReceive (Returning→Received)
  ├ recoverQty = min(orderedQty, receivedQuantity ?? orderedQty)
  ├ applyAfterSalesRestockMulti(orderLineId, recoverQty, "AS<id>")
  │    ├ 读 Sale 分组: { A仓:5, B仓:3 }
  │    ├ 最大余数法分配 recoverQty=4 → { A仓:3, B仓:1 }
  │    └ 逐仓 adjustStockForLocation(+qty) → 每仓一条 afterSales:in
  ├ 落 restockJson = [{A仓:3},{B仓:1}]
  └ request.state = 'Received'
```

## 六、整数分配算法（最大余数法）

按各仓发货比例计算回补量：

1. 每仓比例分配量 = `recoverQty × (仓发货量 / 总发货量)`
2. 每仓取 `floor`（向下取整），得到初始分配
3. 剩余未分配量 `remainder = recoverQty - Σfloor`，按各仓小数余数从大到小排序，逐仓 +1，直到 `remainder = 0`

示例：发货 A 5 : B 3，退货 4

- 比例：A = 4×5/8 = 2.5，B = 4×3/8 = 1.5
- floor：A=2，B=1，Σ=3，remainder=1
- 余数：A=0.5，B=0.5 → A 先 +1（余数相同取发货量大者优先）
- 结果：A=3，B=1，Σ=4 ✓

**守恒保证**：最大余数法保证各仓回补量均为非负整数且总和精确等于 `recoverQty`。

## 七、错误处理

| 场景 | 处理 |
|---|---|
| 查 `Sale` 失败 / 为空 | `Logger.warn` + 回退单仓（现状逻辑），不阻断 |
| 单仓回补异常 | 现有 try/catch 告警，不阻断收退货/退款 |
| `recoverQty = 0` | 跳过回补 |
| 小数分配 | 最大余数法保证整数且守恒 |

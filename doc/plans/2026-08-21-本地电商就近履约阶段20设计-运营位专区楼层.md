# 阶段20 · 运营位/专区楼层 设计

## 目标
为 C 端首页提供**可后台配置的运营位/专区楼层**。运营人员（admin）配置一系列"专区"（楼层），每个专区承载一组条目（banner 图 / banner 轮播 / 商品 / 纯链接），按 position 排序、可独立启停、按渠道（channel）隔离；C 端首页通过单个查询拉取已启用专区及其条目直接渲染，也可按 code 精准取某一运营位。

## 边界
- 纯「配置 + 展示」能力，新插件 `operation-plugin`（普通 Object 实体，非常用 customFields）。
- 管理端 admin-api 配置专区与条目；C 端 shop-api 只读拉取 `enabled` 专区。
- 商品条目复用 core `Product`（repository/lib 引用）；banner 图关联 core `Asset`（imageAssetId → 解析 `imageUrl`）。
- **不做**：投放周期/定时、人群定向、AB 试验、曝光统计、collection 目录树展开。专注「专区-条目-排序-启停-渠道隔离」原子能力（后续阶段再扩展定向与效果统计）。
- 仅涉及首页楼层聚合，不注入订单/履约/Marketing 链路。

## 数据模型
新插件 `operation-plugin`，两个实体：

### OperationSection（专区/楼层）
| 列 | 类型 | 说明 |
|---|---|---|
| id | PK | VendureEntity |
| code | varchar NOT NULL, unique | 运营位编码，C 端按 code 精准拉取（如 `home_banner`） |
| name | varchar NOT NULL | 后台展示名 |
| type | varchar NOT NULL | 渲染类型：`banner` / `products` / `link` |
| displayMode | varchar | 条目的渲染方式：`carousel`（轮播） / `grid`（宫格） / `list`（列表）；banner 通常 carousel |
| enabled | boolean NOT NULL default true | 启停开关，C 端只输出 enabled |
| position | int NOT NULL default 0 | 楼层排序（越大越靠前） |
| channelId | int NOT NULL | 渠道隔离（普通列，对齐阶段17铁律） |
| createdAt/updatedAt | 自动 | VendureEntity 提供 |

- `code` 全局唯一（跨渠道，避免 code 歧义）。
- 实现 `ChannelAware`（ManyToMany Channel + JoinTable），channelId 用普通列显式赋值。

### OperationItem（专区条目，1-* 属于 section）
| 列 | 类型 | 说明 |
|---|---|---|
| id | PK | VendureEntity |
| sectionId | FK operation_section.id | 所属专区（ManyToOne） |
| type | varchar NOT NULL | `banner` / `product` / `link` |
| sortOrder | int NOT NULL default 0 | 条目内排序（升序） |
| title | varchar NULL | banner/link 标题 |
| imageAssetId | ID NULL | banner 图（关联 core Asset） |
| linkUrl | varchar NULL | banner/link 点击跳转目标 |
| productId | int NULL | type=product 时关联 core Product |
| channelId | int NOT NULL | 冗余渠道（对齐审阅，防跨渠道） |

- 关系：`OperationSection.items`（OneToMany，`: OperationItem[]`），`OperationItem.section`（ManyToOne）。
- 条目写回使用「整段替换」语义（见 API），故 section 保存即覆盖 items，无需级联删除散件。

## API

### Admin API（admin-api，`@Allow(Permission.UpdateSettings)`，平台运营配置）
Query：
- `operationSections(options: OperationListOptions): [OperationSection!]!` — 全量列表（含 items，按 position 排）
- `operationSection(code: String!): OperationSection` — 按 code 查

Mutation：
- `createOperationSection(input: CreateOperationSectionInput!): OperationSection!`
- `updateOperationSection(id: ID!, input: UpdateOperationSectionInput!): OperationSection!`
- `deleteOperationSection(id: ID!): Boolean!`
- `setOperationItems(sectionId: ID!, items: [OperationItemInput!]!): [OperationItem!]!` — **整段替换**条目（删旧插新、按输入 sortOrder 排，幂等）

Input：
- `CreateOperationSectionInput { code!, name!, type!, displayMode?, position?, enabled? }`
- `UpdateOperationSectionInput { name?, type?, displayMode?, position?, enabled? }`（code 建后不可变）
- `OperationItemInput { type!, sortOrder!, title?, imageAssetId?, linkUrl?, productId? }`

### Shop API（shop-api，`@Allow(Permission.Public)`）
Query：
- `operationSections(options: OperationListOptions): [OperationSection!]!` — 仅 `enabled`，按 position 降序；items 按 sortOrder 升序
- `operationSection(code: String!): OperationSection` — 按 code 取单个运营位（仍只出 enabled，未启用返回 null）

条目解析（Item ResolveField）：
- `imageUrl: String` — 由 imageAssetId 解析 core Asset 的 `preview` 地址
- `product: Product` — type=product 时懒加载返回 core Product（批量加载防 N+1）

## 服务 operation.service.ts
- 注入 `TransactionalConnection`、`ProductService`（取商品）、`AssetService`（解析图）。
- Admin CRUD：create/update/delete section；`setOperationItems` 用事务「删旧 + 全量插入」（对齐 favorite 事务风格）。
- Shop 读取：`findEnabledSections(ctx)`（channelId 过滤 + enabled + position DESC + eager items sortOrder ASC）；`findByCode`。
- product ResolveField：收集该 channel 下所有 item 的 productId → 批量 `getRepository(Product)` 一次取回，按 id 建 Map，避免 N+1。
- imageUrl ResolveField：批量取 Asset 建 Map，同理防 N+1。

## 安全 / 隔离
- admin：`@Allow(Permission.UpdateSettings)`，仅平台运营可配置。
- shop：`@Allow(Permission.Public)`，只暴露 enabled 专区 + 白名单字段，含 `imageUrl`/`product` 详情；不暴露 channel 内部信息。
- 渠道隔离：admin 与 shop 读取一律按 `ctx.channelId` 过滤；`code` 虽全局唯一，但展示数据随渠道隔离。

## 性能
- 读路径：一次 `find({ where: { channelId, enabled } })`（items eager 随取）。
- 条目商品/图片解析：批量 Map 缓存（一批 item 只发一次 DB 查询），无 N+1。

## 依赖
- peer：`@vendure/core`（Product / Asset / RequestContext / TransactionalConnection）。
- 不依赖 shop-plugin（不需要在专区里直接 render 店铺对象；商品即足够）。
- e2e 注册 `OperationPlugin.init()` + ShopPlugin 骨架（如需 product 数据经 shop-api）。

## 构建/部署
- lib 本地 `tsc` 构建入库；服务器 `git pull + pm2 restart`（部署铁律，不在服务器构建）。

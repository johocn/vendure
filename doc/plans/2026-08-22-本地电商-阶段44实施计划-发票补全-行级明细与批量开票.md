# 阶段44 实施计划：发票补全 —— 行级明细快照 + 批量/自动开票 + 抬头复用 + 发票号规则

> 目标：在阶段43「C端申请→后台开票→PDF下载 + 抬头管理」基础上，补齐发票域生产可用性：
> ① 发票不再只存订单ID合计，开票时固化**行级明细快照**（含价税分离），发票与订单解耦、防拖单变更漂移、支持红冲按快照校验；
> ② 后台**批量开票/自动开票**，释放人工逐单 issue 的负担；
> ③ `createInvoice` 支持 `invoiceTitleId` **后端拉抬头快照**，前端不必重复填抬头字段；
> ④ 统一**发票号生成规则**（唯一、可追溯）；
> ⑤ 轻量**发票合规校验**（专票必填同类、税号格式）。
> 现状：invoice-plugin 已具备 Invoice(含 orderIds simple-json/amount/customerId/抬头字段/providerInvoiceNo/pdfUrl/issuedAt/reversedAt/reverseReason/lastError)、InvoiceStatus(PENDING/ISSUED/REVERSED/FAILED)、InvoiceType(ordinary/special/electronic)、Provider 抽象(NoopInvoiceProvider/PdfInvoiceProvider)、InvoiceTitle 抬头库。**缺**：开票明细快照、批量/自动开票、抬头快照复用、统一发票号、合规校验。

## 1. 范围与验收（本次）

### A. 发票行级明细快照 + 价税分离
- Invoice 新增 `lines`(simple-json)：`[{ orderCode, orderId, sku, name, unitPrice, quantity, amount, taxRate, taxAmount, amountWithTax }]`，`priceExcludesTax` + `totalExcludingTax` + `totalTax`.
- `issueInvoice` 时由 provider/服务按 orderIds 聚合订单行生成快照**固化到 Invoice**（此后 PDF 与 myInvoice 详情展示均用快照，订单变更不影响已开票）。
- PDF ordinary/special 模板改为读快照 `lines`（支持多单合并，含税率/税额列）。
- Shop schema：`myInvoice(id)` 新增 `lines` ResolveField 或扩 `Invoice` 类型字段 `{ lines: [InvoiceLine!]! }`。
- **验收**：建票含多单 → issue → `myInvoice(id){ lines totalTax }` 行数与税额正确；改订单后发票快照不变。

### B. 后台批量开票 + 自动开票开关
- Admin mutation `bulkIssueInvoices(ids: [ID!]!): [Invoice!]!`：逐张校验 PENDING→ISSUED，事务化，成功/失败逐张返回（含 lastError）。
- Admin option `autoIssue: boolean`（默认 false）：为 true 时，订单进入可开票状态（Delivered/Completed）且存在对应该单的 PENDING 发票时，`onStateTransition` 自动 trigger issue。**默认关**，避免意外开票。
- **验收**：admin 建 3 张 PENDING → bulkIssue → 3 张全 ISSUED 且 PDF 可下载；partial invalid 单不阻塞其他；autoIssue 开关与触发。

### C. 抬头复用（createInvoice 支持 invoiceTitleId）
- `CreateInvoiceInput` 增可选 `invoiceTitleId: ID`：提供时后端从抬头库拉取当前用户该抬头，回填 taxNumber/email/companyAddress/companyPhone/bankName/bankAccount 快照到 Invoice，并校验归属（非本人抬头→Forbidden）；不提供时维持手填。
- vshop invoice-apply：提交时把所选抬头 `id` 一并传 `invoiceTitleId`，减少手填/错传。
- **验收**：C 端选已存抬头提交 → 后端自动带税号/开户行等到 Invoice 与 PDF；传他人抬头 id → Forbidden。

### D. 统一发票号规则
- `PdfInvoiceProvider` 生成 `invoiceNo` 规则改为 `INV-{yyyyMMdd}-{channelId}-{seq}`，seq 取自当前 channel 当日发票计数（缺 DB 计数则时间戳尾）。保证跨渠道唯一、可读、可追溯。
- Invoice 支持 `invoiceNo` 快照列（=`providerInvoiceNo` 回填），前端可直接展示。
- **验收**：同渠道同日多张不重复；不同渠道隔离。

### E. 发票合规校验（轻量）
- `createInvoice`/`issueInvoice` 前校验：
  - 专票(special)必填：同抬头三要素（开户行/账号/地址/电话）、税号；
  - 税号格式：15/17/18/20 位字母数字（校验失败 UserInputError，仅提示不强制，因为 mock provider 仍可开）。
- **验收**：special 缺税号 → 创建报错带明确 message；税号位数非法 → issue 报错。

## 2. 关键设计
- **行快照与订单解耦**：`lines` 一击固化，PDF 模板、Shop 展示、红冲对照全部读快照；`orderIds` 仍保留用于唯一性校验。
- **价税分离**：复用 OrderService 加载行 + `ProductVariant.taxCategory`/价格计算取 `unitPriceWithTax/unitPrice/linePrice*`，`taxAmount = linePriceWithTax - linePrice`（pricesIncludeTax 场景）；存快照，模板直接印净额/税率/税额/价税合计。
- **批量/自动开票走同一 `issueInvoice` 内核**：bulkIssue 循环调 `issueInvoice`；autoIssue 用 `onStateTransitionEnd` 事件 + 该事件 order 需 findOne 重载（记忆：事件关系不完整）。
- **provider.init 已就绪**：阶段43 已接入 `provider.init(injector)`，发票号计数用 Injector 拿 repository（避免注入 service 环路）。

## 4. 后续方向（写入计划，供后续阶段选择排期）
> 以下为发票域及相邻域的候选方向，**不在阶段44实施**，仅登记，供用户后续指定下一阶段时优先选取：
1. **对接真实电子发票服务商/税局**（Provider 生产化：开票/验真/红冲同步、发票要素上报、专普票纸票）。阶段43/44 已把 Provider 解耦，接税控只新增 provider 不改业务层。
2. **发票开具通知触达**（订单/发票状态变更 → 消息中心 push，复用阶段23 message-plugin 触达通道）。
3. **后台发票中心 UI**（admin 列表筛选/批量开票/导出 Excel，替代 GraphQL 手工调用）。
4. **红冲/作废增强**（部分红冲、作废留痕、红冲后重开同一订单）。
5. **商品维度的库存盘点/调拨/供应商补货增强**（若发票方向告一段落，切换到仓库能力完整化）。

## 5. 非目标
- 不接真实税控/第三方电子发票服务商（留生产/后续方向1）。
- 不做发票开具通知触达（后续方向2）。
- 不做后台发票中心 UI（后续方向3）。
- 不做部分红冲/作废重开（后续方向4）。
- autoIssue 默认关闭，不强制开启。

# 阶段28 设计：到店核销 / 本地生活服务券

> 目标：让商家把"到店服务"（餐饮、饮品、体验、美容美发等）作为服务型商品销售，用户下单获得电子到店券，到店向店主出示，店主本人扫码/输码核销。支持直核销与预约双模式，完整衔接已建的订单/支付/退款/结算/店铺体系。

## 业务闭环

```
商家上架服务型商品(服务标记) → 用户下单支付(免配送/免库存) → PaymentSettled 自动生成到店券(code)
  → (预约品类)另行生成预约档 VoucherBooking
  → 用户到店出示券码 → 店主本人核销 → 券置 used，结算明细含该单
  → (未使用未过期)可退款 → 券置 refunded 失效
  → (到期未核销)自动置 expired
  → (特殊情况)店主/admin 可延期 / 换发作废旧码补新码
```

## 技术路线

- 新插件 `@vendure/voucher-plugin`，沿用既有四件套（package.json/tsconfig/vitest/index），`@Allow` 店主域鉴权复用阶段18，金额统一分（bigint），本地 `tsc` 构建 lib 入库，e2e 在插件目录内跑。

## 核心实体

### ServiceVoucher（到店券）
- `orderId`（int）、`customerId`（int）、`shopId`（int）、`channelId`（int 普通列 NOT NULL + ManyToMany Channel 满足 ChannelAware）
- `productVariantId`（int）、`productVoucherName`（varchar 快照，冗余商品名避免依赖商品）、`code`（varchar，`unique: true` 防碰撞）
- `status`：varchar，`usable | used | expired | refunded | voided`，`@Column({ type: 'varchar' })` 防 sqljs Object
- `effectiveDays`(int 快照) → `expiresAt`(datetime，成交+有效天数)、`usedAt`(datetime nullable)、`refundedAt`(datetime nullable)
- `unique(orderId)` 幂等（一单只生成一次）

### VoucherBooking（预约档，仅预约品类）
- `voucherId`、`customerId`、`shopId`、`channelId`
- `slotAt`(datetime 预约时段)、`customerCount`(int 人数)
- `status`：varchar `booked | visited | noShow | cancelled`，`@Column({ type: 'varchar' })`
- 直核销品类不产生；爽约 noShow、取消 cancelled 倒闲置券

## 载体与生成

- `Product.customFields.serviceType`（varchar,nulable,public）标记服务型变体；命中则该变体商品免配送、免物流单、免库存扣减（下单时按 trackInventory=false 语义处理）。
- 店归属判定：订单主商品 `productVariant.productId → Product.customFields.shopId`（阶段24/26 铁律，OrderLine 无私货 productId，须 `productVariant.productId`）。
- 生成时机：`PaymentSettled` 后按订单内该变体件数生成 `ServiceVoucher`（每件一券），code 懒生成幂等（复用阶段26 getOrCreate 思路）。

## 核销主体与流程

- 仅店主本人：复用阶段18 店主域 `requireMyShop`（`administratorService.findOneByUserId → getRepository(Shop).findOne({administratorId})` + `status==='active'`，直接仓储查 Shop 勿注入 shop service 防 DI 环）。
- admin mutation：`scanVoucher(code)`（查询展示）、`redeemVoucher(code)`（核销：usable→used，写 usedAt）。
- shop mutation：`myVouchers`（当前登录顾客的券列表，含状态/有效期/核销码）、`redeemVoucher` 仅店主域。

## 有效期与退款

- effectiveDays 成交起算（商品可配，默认 90 天）；到期未核销由 JobQueue 扫描置 `expired`。
- 未使用（usable）且未过期可退：联动阶段11/24，退款成功后券置 `refunded`（失效），结算明细相应。
- 特殊操作（店主/admin）：`extendVoucher(voucherId, days)` 延期、`exchangeVoupler(voucherId)` 换发（作废旧码 voided，生成新码 usable）。

## 直核销 + 预约双模式

- 按 `Product.customFields.serviceType` 决定：直核销品类（随到随用，无需预约）与预约品类（下单后同时生成 `VoucherBooking`）。
- 预约到店核销时同步 `booking status → visited`；未到（noShow）/取消（cancelled）由 JobQueue/事件处理倒闲置券。

## 与已建体系衔接

- 订单/支付：复用 core，服务型商品免配送。
- 退款：阶段11 售后可对服务券发起，退款侧重置券失效。
- 结算：阶段24 `merchantAccount/结算明细` 含服务券订单，店口径 = 订单达 Delivered（若无扩展状态机则支持直接结算服务单，需确认结算对无物流单的触发）。
- 店铺：阶段17/18 店主域鉴权与 Shop 归属。

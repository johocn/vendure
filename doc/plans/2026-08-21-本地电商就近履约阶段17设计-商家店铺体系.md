# 阶段17 · 商家店铺体系（多商家/店铺主页/商品归属/店铺评分）设计

> 承接：本地电商就近履约方案（阶段16 商品评价体系已上线）
> 目标：构建第一批**商家店铺闭环**——店铺实体与主页、商品归属店铺、店铺评分聚合、店铺开店与审核，为"本地多商家 + 就近履约"提供商家侧运营基座。

## 1. 背景与现状

现有底座已具备的商家/店铺相关能力（复用而非重建）：

- **Channel 即店铺/门店维度**：dev-server 种子已有多渠道（shop-a 等），`cjk-plugin` 通过 Channel 解析当前 shop（`tenant-channel-custom-fields.ts`、`domain-shop.resolver.ts`），渠道即租户/店铺。
- **履约点 StockLocation**：`MatrixStockLocationStrategy` 把 `OrderLine` 分配到具体 `StockLocation`（门店/履约点），`OrderLine.customFields.stockLocationId/stockLocationsJson` 记录归属；`Product.customFields.belongCity/serviceCities`、`StockLocation.serviceCities` 承载就近履约范围。
- **商品评分**：`review-plugin` 已把评价聚合写入 `Product.customFields.reviewRating/reviewCount`（public），是"真实口碑"数据源。

阶段17 在这些基础上补齐**商家（店铺）一级的主体**：目前 Channel 只是租户维度，没有可作为店铺主页对外展示的店铺档案、也没有"商品—店铺"的显式归属与店铺级评分。目标就是补上这一层。

| 能力 | 现状 | 阶段17目标 |
|---|---|---|
| 店铺实体 | ⚠️ 仅 Channel（无店铺档案） | 新增 `Shop` 实体：名称/slug/logo/banner/简介/状态 |
| 店铺主页 | ❌ | C 端 `shop(slug)` 查询：档案+评分+商品数+店铺商品列表 |
| 商品归属店铺 | ❌ | `Product.customFields.shopId` 显式归属 |
| 店铺评分 | ❌ | 由店铺下所有商品的 `reviewRating/reviewCount` 聚合成店铺级评分 |
| 开店/审核 | ❌ | 管理端创建/更新/封店/审核，店铺商品分配 |

## 2. 核心设计决策

### 2.1 新增独立 `Shop` 实体（不直接复用 Channel 实体）
- 理由：Channel 承担"渠道 token/租户"职责，复用会造成店主登录态与店铺归属、渠道级权限耦合混乱。新增 `Shop` 作为**纯店铺档案主体**，`ChannelAware`（归属某个 channel），与现有就近履约多渠道模型并存。
- `Shop` 字段：`name`、`slug`（唯一、用于 C 端 URL 与查询）、`logoAssetId`、`bannerAssetId`、`description`、`status`(`applicant|active|closed`)、`ownerId`(Administrator/User 主键，店主后台账号)。
- 类型列沿用字符串枚举/`simple-json`，避免跨库（sqljs/PostgreSQL）枚举类型风险（阶段11/12 已实证）。

### 2.2 商品归属店铺——`Product.customFields.shopId`（简单、显式）
- 用 `Product` public 自定义字段 `shopId`（int，nullable）记录店铺归属，不另建店-品中间表，读取与统计最直观。
- 归属只在管理端 `assignProductsToShop` / `unassignProductsFromShop` 变更；下单/结算不依赖该字段。

### 2.3 店铺评分聚合（复用 review-plugin 的 Product 评分）
- 店铺级指标：`ShopRating { rating: Float, reviewCount: Int, productCount: Int }`。
  - `rating`：店铺下所有 `shopId` 归属商品的 `customFields.reviewRating` 的**按 reviewCount 加权平均**（一位小数）。
  - `reviewCount`：所有归属商品 `customFields.reviewCount` 求和。
  - `productCount`：归属商品数（由服务按 `Product.customFields.shopId` 统计）。
- 为保证真实且不跨插件强耦合：`getShopRating(shopId)` **实时扫描**该店归属商品的 `reviewRating/reviewCount` 聚合返回（始终正确）；同时 `recomputeShopRating(shopId)` 将结果落库到 `Shop.customFields.shopRating/shopReviewCount` 供列表缓存。店铺变更（开店/分配商品/触发刷新）与 C 端 `shop` 查询时调用。

### 2.4 店铺状态与鉴权
- 状态机：`applicant`（申请中，默认）→ `active`（审核通过，对外展示）→ `closed`（封店，商品照常但不对外展示店铺页）。
- 管理端 `shop` 系列 mutation 需 `Permission.Settings`（或 `Permission.ORM`），店铺商品的分配、审核走 admin API。
- 店主后台账号（`ownerId`）不为本次范围：阶段17 聚焦店铺实体/档案/评分/C 端店铺页，店主自营后台账权体系留待后续阶段。

### 2.5 命名与插件
- 新插件：`packages/shop-plugin`（命名规避与 Vendure 官方冲突；zhao 自研统一 `zhao-` 前缀化的源文件内具象名）。
- 沿用各阶段铁律：本地 `tsc` 构建 `lib/` 入库，`PACKAGE=shop-plugin` 跑 e2e。

## 3. 变更清单

### 3.1 实体 `shop.entity.ts`
- `Shop extends VendureEntity implements ChannelAware`：`name/slug/logoAssetId/bannerAssetId/description/status/ownerId` + `channelId`(int 列) + `channels`(ManyToMany)。`slug` 唯一索引。
- `get rating/reviewCount` **不落列**——评分来自 `Shop.customFields` 缓存（nullable float/int）+ `ShopRating` 实时重算，避免每次读店多表联查。

### 3.2 店铺自定义字段 `shop-custom-fields.ts`
- `Product.shopId`（int，nullable，public）。
- `Shop.shopRating`（float，nullable）、`Shop.shopReviewCount`（int，nullable）、`Shop.shopProductCount`（int，nullable）——列表缓存用。

### 3.3 服务 `shop.service.ts`
- 管理端：`createShop / updateShop / setShopStatus / assignProductsToShop / unassignProductsFromShop / shops(list) / shop(id)`（含 `recomputeShopRating`）。
- C 端：`shops`（仅 active）、`shop(slug)` → 档案 + `ShopRating` + 店铺商品列表（按 `Product.customFields.shopId`，统一 `listQueryBuilder`）。
- `recomputeShopRating`：读店铺归属商品 → 加权平均写 `Shop.customFields`（`updateCustomFields` 新对象写库，阶段10 教训）。

### 3.4 GraphQL Schema（plugin.ts）
- shopApiExtensions：
  - `type Shop { rating: ShopRating!, productCount: Int! }`
  - `type ShopRating { rating: Float!, reviewCount: Int!, productCount: Int! }`
  - `extend type Query`: `shops(options): [Shop!]!`、`shop(slug: String!): Shop`。
  - `extend type Product` 无需改（shopId 是内联 customFields；店铺商品列表用 `shop.products`）。
- adminApiExtensions：
  - `extend type Mutation`: `createShop(input): Shop`、`updateShop(id, input): Shop`、`setShopStatus(id, status): Shop`、`assignProductsToShop(input): Boolean`、`unassignProductsFromShop(input): Boolean`。
  - `Shop.products`: ResolveField 分页返回店铺商品。
- configuration：注册上述自定义字段（`mergeCustomFields` 幂等并入 Product/Shop）。

### 3.5 类型 `types.ts`
- `ShopListOptions`、`ShopRating`、`ShopStatus`、`CreateShopInput`、`UpdateShopInput`、`AssignProductsInput`。
- `ShopPluginOptions`（预留）。

### 3.6 工程配套（对齐各阶段）
- `vitest.config.mts`、`tsconfig.build.json`、`e2e/shop.e2e-spec.ts`（含 `e2e/__data__`）。

## 4. 测试策略（e2e）

SQLite(sqljs) + @vendure/testing，覆盖真实全链路：

1. **插件可加载；无店铺时 `shops` 空、店铺默认评分 0/0**。
2. **开店与审核**：管理端创建店铺（applicant）→ `setShopStatus` 置 `active`，C 端 `shops` 出现、`closed` 不对外。
3. **商品归属店铺**：`assignProductsToShop` 后某商品归店，店铺商品列表包含该商品；`unassign` 后移除。
4. **店铺评分聚合**：给归属商品写 `Product.customFields.reviewRating/reviewCount`（模拟 review-plugin 结果），`recomputeShopRating` 后 `shop(id).rating` 加权平均正确、reviewCount 求和正确、productCount 正确。
5. **店铺主页**：`shop(slug)` 返回档案 + 评分 + 商品数 + 店铺商品列表；slug 不存在返回 null。
6. **校验与越权**：slug 重复建店被拦截；未授权 mutation 被 Forbidden。

## 5. 风险与权衡

- **`Shop` vs `Channel`**：新增独立实体避免与渠道租户语义耦合；店铺商品用 `shopId` 显式归属，避免与渠道分配混在一起。
- **评分实时 vs 缓存**：C 端 `shop` 查询实时聚合保证正确；`Shop.customFields.shopRating` 仅作列表缓存，避免 N+1。
- **店主账号**：本阶段不实现店主自营登录/账权，仅管理端运营；避免范围膨胀。
- **cross-plugin 解耦**：shop-plugin 读 `Product.customFields.reviewRating`，不直接依赖 review-plugin 内部实现（只依赖字段契约）。
- 实体日期/类型列沿用 `?: Date` 写法；字符串状态用 `varchar` 列（阶段11/12 教训）。

## 6. 交付与部署

- 工程铁律：本地 `tsc -p packages/shop-plugin/tsconfig.build.json` 产出 `lib/` 并入库；服务器 `git pull` + `pm2 restart`，**不在服务器构建**。
- shop-plugin 产物 `lib/` 须纳入 git 跟踪；`e2e/__data__/*.sqlite` 被根 `.gitignore` 忽略。

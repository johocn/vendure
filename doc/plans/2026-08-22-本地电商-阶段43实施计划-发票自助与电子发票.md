# 阶段43 实施计划：发票自助 + 电子发票

> 目标：打通「C端申请发票 → 后台开票 → 电子发票PDF下载」闭环，新增「发票抬头管理」。
> 现状：invoice-plugin 已具备 C端申请(createInvoice/myInvoices/downloadInvoicePdf)+后台开票/冲红(issueInvoice/reverseInvoice)+Invoice 实体+Provider 抽象；invoice-pdf-plugin 已有 PDF 生成/存储服务(InvoicePdfService)。**缺**：① 二者未打通（invoice-plugin 默认 Noop provider 不产出可下载 PDF）；② 无抬头资料统一管理；③ vshop 无任何发票前端页。

## 1. 范围与验收（本次）

- **发票抬头管理**：新增 `InvoiceTitle` 实体（单位抬头/税号/邮箱/地址/电话/开户行/账号/isDefault + customerId + ChannelAware）。C端保存/复用/设默认/删除。
- **电子发票下载**：新建 `PdfInvoiceProvider`（置于 invoice-pdf-plugin，实现 invoice-plugin 的 `InvoiceProvider`），`issue` 时按 `orderIds` 聚合订单行 → 用现有 ordinary/special 模板生成单张 PDF → 存 assets → 回填 `pdfUrl`；`queryPdf` 返回 pdfUrl；`reverse` 本地冲红。dev-config 用 `InvoicePlugin.init({ provider: new PdfInvoiceProvider() })` 接线。
- **vshop C端页**：发票申请页（选已支付订单 + 选已存抬头）、我的抬头管理、发票列表/下载。
- **验收（e2e-sso 同款 `tools/e2e-invoice.mjs`）**：建抬头→申请发票→后台 issue→pdfUrl 生成→C端 downloadInvoicePdf 可取到 URL。全部无外部依赖。

## 2. 关键设计

### 1) 抬头管理（invoice-plugin 新增）
- `InvoiceTitle` 实体字段：`title`(required,text)、`taxNumber`、`email`、`companyAddress`、`companyPhone`、`bankName`、`bankAccount`、`customerId`(number)、`isDefault`(bool,default false)、ChannelAware。
- Shop schema：
  - mutations：`createInvoiceTitle(input)`、`updateInvoiceTitle(id,input)`、`deleteInvoiceTitle(id)`、`setDefaultInvoiceTitle(id)`（同一 customer 同渠道置唯一默认）。
  - queries：`myInvoiceTitles: [InvoiceTitle!]!`。
- 归属校验：仅本人（`customerId === ctx.activeUserId`）可读写删；删除默认抬头时自动转 try 归还无（不可保留孤儿默认）。

### 2) 电子发票打通（invoice-pdf-plugin 新增 PdfInvoiceProvider）
- `InvoicePdfService` 新增 `generateCombinedPdf(ctx, input: IssueInvoiceInput, orders: Order[]): Buffer`：聚合各行 item→调用 ordinary/special 模板；输入含 invoiceNo/title/taxNumber/邮箱/地址/电话/开户行/账号/orderCodes[]/orderTotal/orderDate/lines[]。
- `PdfInvoiceProvider implements InvoiceProvider`：
  - `config={code:'pdf',name:'自动生成PDF'}`；`init(injector)` 取 `InvoicePdfService`+`AssetStorageStrategy`+`OrderService`。
  - `issue(ctx,input)`：取 orders（orderIds）→ `generateCombinedPdf` → `assetStorageStrategy.writeFileFromBuffer` → `toAbsoluteUrl(fileName)` 得 pdfUrl → 返回 `{success:true, invoiceNo:'INV-'+orderCode 或时间戳, pdfUrl}`。
  - `queryPdf(ctx,invoiceNo)`：需能由 invoiceNo 复原 fileName（invoiceNo 编码 order.id/时间戳，正则解析）→ 返回 pdfUrl。
  - `reverse`：本地冲红，`{success:true}`。
- 跨包依赖：invoice-pdf-plugin 的 `devDependencies`/`peerDependencies` 增加 `@vendure/invoice-plugin`（仅类型；程序运行在 vendure monorepo 内，workspace 解析）。
- 去环路检查：invoice-pdf-plugin 不 import invoice-plugin 的 service（仅类型/枚举），无循环。

### 3) invoice-plugin 接线 provider
- `InvoicePluginOptions.provider` 保持；plugin 增加：若 provider 具 `init`，`onApplicationBootstrap` 时调用 `provider.init(this.injector)`（Noop 无 init，兼容）。
- dev-config：`InvoicePlugin.init({ provider: new PdfInvoiceProvider() })`。

### 4) vshop C端页（vshop 目录）
- 我的-发票：`/user/invoice` — 发票申请（列表勾选已支付订单+选抬头+填税号）、`/user/invoice/titles` 抬头管理、发票列表项「下载PDF」（打开 pdfUrl）。
- 复用登录态 bearer；走 shop-api `Invoice` 相关 mutation/query。

## 3. 涉及文件

- invoice-pdf-plugin：新增 `src/pdf-invoice.provider.ts`、`src/templates/combined.ts`（或扩展 service）；改 `src/invoice-pdf.service.ts`、`src/plugin.ts`（导出 provider）。
- dev-config.ts：`InvoicePlugin.init({ provider: new PdfInvoiceProvider() })`。
- vshop：新增发票相关页面 + API 封装。
- tools/e2e-invoice.mjs。

## 4. 非目标
- 不接真实税局/第三方电子发票服务商（本地无依赖验收，留生产）。
- 不改造 admin 开票 UI（已有 issue/reverse 后台入口）。

# 阶段27 · 设计（社区团购/团长体系）

依据：本地电商已有订单（Vendure core + 周期购/自提），按店发货履约（阶段5/8-10），店铺与店主账权（shop-plugin 阶段17/18），收货地址与配送范围（address-plugin 21/22），对账结算（settlement-plugin 阶段24 抽佣/商家应收/提现），门店自提闭环（pickup-plugin 阶段26 固定提货码+一次性核销），消息触达（notification-plugin 阶段23）。

社区团购是社会链裂变 + 就近履约的典型本地电商场景：**团长**（经审核的买家/捡货人）绑定自提点开"社区团"（只在开放期内精选平台店铺商品、设定截单时间）；**邻居**通过团长链接参团，订单仍走各店正式订单与履约、到自提点取货；**结算**照常按店走阶段24，平台为团长单列"商家让利"佣金并按成交额联动结算、计作团长个人分账。

核心定位：这是个**团长分销闭环**——"选品入口 + 截单集单 + 分账"三件事，**不自建货架、不重造订单与结算**。边缘清晰，复用具自提/履约/结算/抽佣模块。

## 1. 目标与非目标

**目标**
- 团长入驻与审核：买家申请（绑定自提点）→ 平台审核 → active 后可开团。
- 开团：团长从平台店铺商品选品（variant/活动价/限量），设开放窗口 + 截单时间 + 佣金率 + 自提点。
- 邻居参团下单：活动链接入口 → 生成正式 `pickup` 订单（自提点=活动自提点）→ 绑定到活动（幂等）。
- 截单成团：到截单时间成团（1 人也发）→ 期内已付款参与订单进入履约；截单只触发一次。
- 结算单列佣金：参与订单照常走阶段24按店结商家应收；平台单列"商家让利"＝参与成交额×佣金率，商家应收体现扣减，生成团长佣金单并累计。
- 权限隔离：团长（Owner 且 active）、商家（被选品店铺）、平台（审核/全局）。

**非目标**
- 不做团长侧真实独立货架/自营供应链（团长卖的是平台店铺商品，无自建供应链）。
- 不做成团人数下限 / 未达标退款（截单集单，1 人也发；无人数门槛）。
- 不做团长佣金的真实支付网关提现（本期只"记"佣金并累计，不复用阶段24提现状态机；如需支付走后续阶段）。
- 不做抢购/限量摇号等营销（限量仅在开团时设定，下单前校验）。

## 2. 总体架构

```
团长入驻(buyer→apply，绑自提点) → 平台 approve → leader active
链团长开团：选品(variant/price/限量) + 窗口 + 截单 + 佣金率 + 自提点 → 活动 draft→open

邻居经团长链接参团 → 下单(自提点=活动自提点, deliveryType=pickup)
  → 生成正式订单 → 写 CommunityParticipation(activity,leader,subtotal)【唯一(activityId,orderId)幂等】

到截单 → 活动 cutover（系统触发，幂等仅一次）→ 期内已付款参与订单进入履约
  → 各店履约/就近配送 → 阶段24按店结算 商家应收

结算时单列团长佣金：成交额×佣金率（商家让利）→ 商家应收扣减 + CommunityCommissionEntry 归团长
  → 累加 leader.totalCommission（可查，可后续接提现）
```

## 3. 数据模型（`packages/community-plugin/src/`）

统一继承 core 基类（id/createdAt/updatedAt），ChannelAware（`channelId` + `@ManyToMany(()=>Channel) @JoinTable() channels` 阶段26实证写法），日期列 `@Column({type:'datetime',nullable:true}) xxx?: Date`。

### 3.1 CommunityLeader（团长）
| 列 | 类型 | 说明 |
|---|---|---|
| `userId` | int | 关联买家 User（审核买家） |
| `customerId` | int | 关联 Customer |
| `pickupLocationId` | int | 绑定自提点（衔接 phase26） |
| `status` | varchar default 'applied' | `applied/active/suspended` |
| `totalCommission` | bigint default 0 | 累计佣金(分) |

索引：`unique(userId)`。

### 3.2 CommunityActivity（社区团/活动）
| 列 | 类型 | 说明 |
|---|---|---|
| `leaderId` | int | 团长（FK） |
| `pickupLocationId` | int | 自提点 |
| `windowStart` / `windowEnd` | datetime | 开放窗口（下单入口有效区间） |
| `cutoffTime` | datetime | 截单时间（成团触发点） |
| `commissionRate` | bigint | 佣金率（千分比，如 3% = 3000） |
| `status` | varchar default 'draft' | `draft/open/cutover/closed` |

### 3.3 CommunityActivityItem（选品）
| 列 | 类型 | 说明 |
|---|---|---|
| `activityId` | int | FK |
| `variantId` | int | 平台商品变体 |
| `price` | bigint | 活动价(分) |
| `stockLimit` | int nullable | 限量(可选) |

### 3.4 CommunityParticipation（参与/集单体）
| 列 | 类型 | 说明 |
|---|---|---|
| `activityId` | int | FK |
| `orderId` | int | 正式订单（FK） |
| `leaderId` | int | 团长 |
| `subtotal` | bigint | 该单参与成交额(分) |

索引：`unique(activityId, orderId)`（幂等绑定）。

### 3.5 CommunityCommissionEntry（团长佣金单，随结算生成）
| 列 | 类型 | 说明 |
|---|---|---|
| `leaderId` | int | 团长 |
| `orderId` | int | 关联订单 |
| `amount` | bigint | 佣金(分) |
| `status` | varchar default 'pending' | `pending/paid`（本期记账；支付走后续） |

## 4. 编排（CommunityService）

- **入驻/审核**：`applyLeader(ctx)`（Owner，绑自提点，status=applied）；`approveLeader(ctx, leaderId)`（平台，→active）、`suspendLeader`（→suspended）。
- **开团**：`createActivity(ctx, input)`（团长须 active；校验自提点有效、截单在窗口后）→ draft；`openActivity(ctx,id)` → open。
- **参加/绑定**：`participate(ctx, orderId, activityId, subtotal)`——下单链路里调用，校验订单是 pickup、活动 open、在窗口内、未截单、限量未超 → 写 `CommunityParticipation`（幂等：存在则返）。
- **截单成团**：`cutoverActivity(ctx, activityId)`（平台/系统定时）：幂等（仅 cutover 一次）→ 取期内已付款参与订单 → 依次推进各单进入履约（找到待履约 Fulfillment 或推进 order 到 Arranged/Shipped 口径，对齐 core/阶段10 手法）；→ closed。
- **结算单列佣金**：订阅 `OrderStateTransitionEvent`（订单达 Delivered/Completed 且该单有 Participation）→ 计算 `amount=subtotal×commissionRate` → 写 `CommunityCommissionEntry` + `leader.totalCommission += amount`（幂等：unique(orderId+status 或 activity 去重））。商家应收的"单列扣减"通过阶段24扩展/该单结算明细体现（本期以"文档约定 + e2e 断言商家应收含让利扣减语义"落地，具体字段以 settlement 结算明细结构为准）。
- **查询**：`myActivities`（团长)、`myCommission`（团长，含累计）、`participationOf`/`activityParticipation`（平台/商家按需）。

## 5. 权限与归属

- **团长域（shop-api）**：`@Allow(Permission.Owner)`。`applyLeader`、`myActivities`、`myCommission`。团长须 active 才可 `createActivity`。
- **商家域（admin-api）**：`@Allow(manageOwnShop)`。`myShopActivityParticipation`（被选品店铺看其活动参与单）——本次以参与单反查商品归店过滤。
- **平台（admin-api）**：`@Allow(Permission.UpdateSettings)`。`approveLeader`/`suspendLeader`、`communityActivities`/`communityParticipations` 全局查询、`cutoverActivity`。

## 6. GraphQL 接口（示意，实施按现有包 schema 单份手法）

**shop-api · 团长（`@Allow(Permission.Owner)`）**

## 7. 错误处理

- 非 active 团长开团 / 自提点失效 / 截单时间早于窗口 / 窗口外或已截单后下单 / 选品限量超 / 已是 cutover/closed 的活动参团 → `UserInputError`。
- 顶越权：非本人查佣金、非被选品店铺看参与单 → `Forbidden`。
- 截单成团幂等：`cutoverActivity` 仅推进一次，重复调用返回现状不重复履约冻结佣金；`CommunityCommissionEntry` 生成幂等（按 order 去重）。
- 佣金结算幂等：同单不重复累计（先查后写，或依赖 unique 键）。

## 8. 测试（e2e ≥ 12）

复用阶段26 pickup-e2e 骨架（Inventory + Shop + delivery/pickup + Settlement + Community + `singleStageRefundablePaymentMethod`）。覆盖：
1. 插件加载 + 买家申请团长（绑自提点）→ applied
2. 平台 approve → active
3. 团长开团选品（variant/price/限量/佣金率/截单）→ draft
4. open 后邻居经活动下单 → 正式 pickup 参与单 + Participation 绑定
5. 截单 cutover → 活动 closed、期内已付款参与订单进入履约（幂等只一次）
6. 参与单照常走阶段24按店结算（商家应收出现该单）
7. 佣金单列：`subtotal×佣金率` 生成 CommunityCommissionEntry、商家应收体现扣减、leader.totalCommission 累计
8. 佣金幂等：同单不重复累计
9. 幂等参与：同活同单不重复绑定
10. 非 active 团长开团被拒 / 窗口外参团被拒 / 限量超被拒
11. 越权：非本人查佣金、非被选品店铺看参与单 Forbidden
12. 1 人也发：单参与单截单成团照常触发履约

## 9. 风险与前置依赖

- 依赖 settlement-plugin（阶段24）提供商家应收结构，佣金"单列扣减"以其结算明细可用字段为准（实施若缺则用约定字段并在 e2e 断言其语义）。
- 依赖 pickup-plugin/delivery-plugin 的自提点与订单 pickup 语义（下单入口已具备；本插件仅绑定 activityId 和读自提点）。
- 依赖 notification-plugin（阶段23）做团长审核/活动提醒（本期可只留扩展点，不强制打通）。
- 截单为系统定时（JobQueue）或平台手动 `cutoverActivity` 二选一，实施取后端 JobQueue 定时扫描（继承阶段25每日调度）以自动化。
- 团长佣金支付网关/自动提现非本期范围（仅记 `totalCommission`；如需可后续接阶段24提现状态机）。
- 适度规模：单插件单闭环，可一次实施；实施计划分 6 任务（脚手架/实体/Service/装配/调度与结算单列/e2e）。

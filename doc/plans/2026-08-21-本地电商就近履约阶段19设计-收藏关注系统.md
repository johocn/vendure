# 阶段19 · 收藏/关注系统 设计

## 目标
为 C 端用户提供两种轻量关系绑定：**收藏商品**（商品心愿单）与**关注店铺**（店铺订阅）。点击即存、幂等切换、可回溯列表，并在商品/店铺侧体现收藏热度。

## 边界
- 纯 C 端能力，走 `shop-api` + 登录顾客态（`activeUserId → customer`）。
- 关注店铺本体是 shop-plugin 的 `Shop` 实体（lib 引用，防实体双份）；收藏目标是 core `Product`。
- 不做社交、不做推荐位、不注入订单链路。专注「绑定 / 切换 / 列表 / 计数」四个原子能力。

## 数据模型
新插件 `favorite-plugin`，实体 `Favorite`（普通 plugin 实体，非 customFields）：

| 列 | 类型 | 说明 |
|---|---|---|
| id | PK | VendureEntity |
| customerId | int NOT NULL | 收藏者（C 端顾客） |
| productId | int NULL | 收藏商品目标；与 shopId 二者其一 |
| shopId | int NULL | 关注店铺目标；与 productId 二者其一 |
| channelId | int NOT NULL | 渠道隔离（同 review） |
| createdAt | DateTime | 自动 |

- 唯一约束：`(customerId, productId)` 与 `(customerId, shopId)` 各自唯一 → 天然幂等（toggle）。
- 需手动复合索引/唯一约束（TypeORM 用 `@Unique` 或 `@Index` + `findOne` 判重）。

## 计数（热度展示）
- 商品收藏数：写 `Product.customFields.favoriteCount`（int, nullable, public），service 实时 `count({productId})` 后写回（对齐 review 聚合口径）。favorite-plugin 自注册该 customField，无需改他人插件。
- 店铺关注数：**动态 count**（`count({shopId})`），不写 Shop 缓存列——避免修改 shop-plugin 实体造成跨插件联动；收藏/关注为低频读，动态聚合足够。
- 收藏态判定：唯一记录存在即为已收藏/已关注，`count`/`findOne` 决出，无 N+1。

## C 端 API（shop-api，均需登录）

Query：
- `myFavoriteProducts(options: FavoriteListOptions): ProductList!` — 我收藏的商品列表
- `myFollowedShops(options: FavoriteListOptions): ShopList!` — 我关注的店铺列表
- `isProductFavorite(productId: ID!): Boolean!`
- `isShopFollowed(shopId: ID!): Boolean!`

Mutation（toggle，返回叠加后的绑定态）：
- `toggleFavoriteProduct(productId: ID!): Boolean!` — true=已收藏
- `toggleFollowShop(shopId: ID!): Boolean!` — true=已关注

## 服务（favorite.service.ts）
- `requireCustomer(ctx)`：复用 review 口径（`activeUserId` 判空 → `customerService.findOneByUserId`）。
- `toggleProductFavorite(ctx, productId)`：判 product 存在 → 已存在则删（返回 false），否则建（返回 true）；双向维护 `Product.favoriteCount`。
- `toggleShopFollow(ctx, shopId)`：判 shop 存在 → 同上 toggle；维护 `Shop.followerCount`。
- `isProductFavorite` / `isShopFollowed`：查询唯一记录是否存在。
- `myFavoriteProducts` / `myFollowedShops`：join Favorite 表过滤 customerId + 拼接目标详情（复用 `ProductService` 列表 / `ShopService.getShopById`）。

## 性能与一致性
- 写路径：单记录 CRUD O(1)。
- 读列表：先取本用户 Favorite 记录 → 批量取目标详情。
- 计数缓存列在每次 toggle 后重算写回，保证不高频请求时仍接近实时。

## 依赖
- peer 依赖：`@vendure/core`、`@vendure/shop-plugin`（仅 `Shop` 实体，lib 引用）。
- 为提高确定性，收藏商品计数写回 product 也建议经 `ProductService`/Repository 直写 `ProductTranslation` 无关，直接 `connection.getRepository(Product)` 细粒度 update。

## 安全
- 所有操作 `@Allow(Permission.Public)`？否——需登录，用 `@Allow(Permission.Authenticated)`（或读取需登录的守卫）。沿用 review 的 `requireCustomer` 抛 `UnauthorizedError`。
- 越权：仅能操作本人 customerId 的收藏记录。

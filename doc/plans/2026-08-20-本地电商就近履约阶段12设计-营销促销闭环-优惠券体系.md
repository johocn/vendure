# 阶段12 · 营销促销闭环（优惠券体系）设计

> 日期：2026-08-20
> 项目：Vendure 本地化电商（d:\zhao\vendure）
> 前置：阶段11（退款/售后闭环）已完成
> 本文档为设计稿，实施见 companion 文件：`2026-08-20-本地电商就近履约阶段12实施计划-营销促销闭环-优惠券体系.md`

## 1. 背景与目标

阶段10/11 已打通「履约闭环」与「退款/售后闭环」，交易的资金与库存闭环完成。但**营收增长的营销侧**还缺一块：目前仅有秒杀（flash-sale-plugin），无通用营销券能力。

本阶段建设**优惠券（Coupon）体系**，作为「营销促销闭环」，与现有秒杀共同构成完整的价格促销工具箱：

- **已有**：秒杀（限时特价，基于 Vendure 原生 Promotion 条件/动作）
- **本阶段新增**：优惠券（满减/折扣/无门槛），含发券-领券-结算核销-回退的生命周期

核心设计原则：**复用 Vendure 原生 Promotion 结算机制**，券承载于订单自定义字段，由 order-calculator 在结算时自动套用，避免侵入结算状态机。

## 2. 范围

### 2.1 目标（In Scope）
1. **券模板（CouponTemplate）**：后台可配置的券规则（满减/折扣/无门槛、面额、门槛、有效期、发行量、限领、适用范围、生效渠道）
2. **领券中心**：可领取的券模板列表 + 用户领券（原子扣减发行余量，防超发）
3. **用户券包（CustomerCoupon）**：可用/已用/过期/回退 状态管理
4. **结算闭环**：结算选券 → 订单携带券 → Promotion 自动套用 → 支付成功核销 → 取消/退款回退
5. **定向发券**（admin 手动发给指定用户）

### 2.2 非目标（Out of Scope）
- 复杂的券叠加组合（本阶段**一单一张券**；多券叠加留待后续）
- 秒杀价的改造
- 会员等级/积分抵扣（与本阶段不同主题）
- 钱被锁定的预付卡/储值卡

## 3. 领域模型

```
CouponTemplate (券模板)                 CustomerCoupon (用户券)
┌──────────────────────────┐          ┌──────────────────────────────┐
│ id                        │          │ id                           │
│ name                     │          │ customerId                   │
│ type: FIXED|PERCENT|FULL │          │ templateId                   │
│  满减｜折扣｜无门槛        │          │ code (唯一券码,可推广/可展示) │
│ discountValue (面额/折扣) │1──┐      │ status                        │
│ minSpend (满 X 元起,0=无) │   │      │   UNUSED|USED|RETURNED|EXPIRED│
│ startsAt / endsAt         │   └──────│   INVALID                     │
│ totalCount (发行总量,0=不限)│          │ issuedBy: CENTRE|ADMIN        │
│ claimedCount (已领取)     │          │ reservedOrderId (预约锁定单)   │
│ perUserLimit (限领,0=不限)│          │ usedOrderId (已核销订单)       │
│ scope: ALL|CATEGORY|SKU  │          │ issuedAt / usedAt / expiredAt  │
│ categoryId / variantId   │          │ createdAt / updatedAt          │
│ enabled (上下架)          │          └──────────────────────────────┘
│ channelAware             │
└──────────────────────────┘
```

### 3.1 券类型（CouponTemplate.type）
| type | 规则 | demo |
|------|------|------|
| `FIXED` | 满 `minSpend` 减 `discountValue` | 满100减20 |
| `PERCENT` | 满 `minSpend` 打 `discountValue` 折（1-99整数，如 9折） | 满50打8.5折 |
| `FULL` | 无门槛直减 `discountValue`（minSpend=0 强制） | 立减5元 |

> 满减/无门槛落地为**订单级固定折扣**（等价于 core `order_fixed_discount` 的减额语义）；
> 折扣券落地为**订单级百分比折扣**（等价于 core `order_percentage_discount`）。

### 3.2 用户券状态机（CustomerCoupon）
```
                领券(issuedAt)                    支付成功核销(usedAt, usedOrderId)
 UNUSED ──────────────────────► USED ────────────────────────────────────────► ┐
   │  ▲                                │                                        │
   │  │ 取消订单/退款时回退             │ 售后退款不回退券（已消费核销，资金已退）   │
   │  │ (RETURNED, 可再次使用)          └───────────────────────────────────────┘
   │  ▼
   └── 过期(endsAt 已过, EXPIRED)
   作废(admin 撤销领出券, INVALID)
```

- **回退时机**：订单进入 `Cancelled` 时回退（若该单核销过券）。退款（售后）视为已消费不自动回退——与"券已核销、业已消费"一致，避免滥用重复用券。
- **幂等**：回退前检查券当前状态是否为 `USED` 且 `usedOrderId` 对应该单，避免重复回退。

### 3.3 券码（CustomerCoupon.code）
- 唯一随机码（如 `C-XXXX-XXXX`），领取时生成，全局唯一（创建时原子校验唯一索引）。
- 结算时用户以券码选券，订单携带券码，Promotion 以此校验。

## 4. 结算闭环（关键机制）

### 4.1 积分/携券链路
```
结算：
  shop: applyCouponToOrder(code)  → 校验用户拥有且可用 → 写 order.customFields.couponCode + couponId
  （order 变更自动触发 order-calculator 重算 promotions，无需手动触发）
优惠套用：
  couponPromotionCondition.check(): order.customFields.couponCode 非空
                                   + 找到该券模板，校验有效期/类型/门槛(minSpend≤subTotal)
  couponPromotionOrderAction.execute(): 按券类型折算折扣额返回负数
核销：
  OrderPlacedEvent → 该券置 USED(usedAt, usedOrderId)
回退：
  OrderStateTransitionEvent(Cancelled) → 若该券为 USED 且 usedOrderId=本单 → 置 RETURNED
```

### 4.2 与原生 Promotion 的关系
- 复用 core **订单级** promotions（`PromotionOrderAction`），套用整单折扣、自动分摊到 lines（order-calculator 已支持 `applyPriceAdjustments` 分摊整单折扣，见 `order-calculator.ts`）。
- 不新增独立结算钩子，完全跟随 Vendure 原生结算路径，**低侵入、不破坏后续升级**。
- 沿用秒杀同款 `mergeCustomFields` + `promotionOptions.promotionConditions/actions` 注册方式（见 `flash-sale-plugin/src/plugin.ts`）。

### 4.3 规则约束
- **一单一券**：`applyCouponToOrder` 已携券时先清旧再覆写；不允许同时存在多券字段。
- **防超发/防领超**：领券用原子 `UPDATE template SET claimedCount=claimedCount+1 WHERE id=? AND (totalCount=0 OR claimedCount<totalCount)`，affected=0 即不可领；`perUserLimit` 用用户已持 UNUSED 券计数校验。
- **选券校验**：必须是当前 customer 的券、状态 UNUSED、模板 enabled、当期有效、门槛满足订单金额。
- **幂等核销/回退**：均前置状态检查，失败只 `Logger.warn` 不抛，避免破坏订单主流程。

## 5. API 设计（GraphQL）

### 5.1 Admin API（Permission.UpdateOrder / custom "CouponManage"）
```graphql
# Query
couponTemplates(options): CouponTemplateList!
couponTemplate(id): CouponTemplate
customerCoupons(options): CustomerCouponList!        # 全部用户券（可按状态/模板筛选）
# Mutation
createCouponTemplate(input): CouponTemplate!
updateCouponTemplate(input): CouponTemplate!          # 白名单字段，装改 enabled
deleteCouponTemplate(id): Boolean!
grantCoupon(templateId, customerIds): [String!]!      # 定向发券，返回发放券码
revokeCustomerCoupon(id): CustomerCoupon!             # 作废未用券 → INVALID
```
`CouponTemplate` 字段：id, name, type, discountValue, minSpend, startsAt, endsAt, totalCount, claimedCount, perUserLimit, scope, categoryId, variantId, enabled, status(enum), createdAt, updatedAt

### 5.2 Shop API（Permission.Authenticated，当前客户）
```graphql
# Query
couponCentre(take): [CouponTemplate!]!                # 领券中心（enabled + 可领）
myCoupons(status): [CustomerCoupon!]!                  # 我的券包
# Mutation
claimCoupon(templateId): CustomerCoupon!              # 领券（防超发/限领）
applyCouponToOrder(code): Order!                       # 结算选券（写 order customField）
clearCouponFromOrder: Order!                           # 取消选券
```

## 7. e2e 验收要点（coupon.e2e-spec.ts）
1. admin 建满减券（满100减20）→ 用户领券 → 结算选券 → 订单金额扣20 → 支付 → 券 USED + usedOrderId 落单
2. 折扣券（满50打8.5折）金额核算正确
3. 防超发：totalCount=N 时第 N+1 次领券失败；perUserLimit 超领失败
4. 过期：endsAt 已过期不可领不可用
5. 取消订单 → 已核销券回退 RETURNED 可再次使用；退款不自动回退
6. 未达门槛不可选；非本人券不可选；已用券不可选
7. Claimed count/库存原子性（并发 simulate）

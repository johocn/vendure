# 阶段15 · 会员积分闭环（Points Redemption Closure）

> 日期：2026-08-21
> 项目：Vendure 本地化电商（d:\zhao\vendure）
> 前置：阶段12（优惠券）/ 阶段13（拼团）/ 阶段14（秒杀）已完成，Promotion 动态取配置模式已验证（runtime 注入 + condition state 传 action）
> 本文档为设计稿，实施见 companion 文件：`2026-08-21-本地电商就近履约阶段15实施计划-会员积分闭环.md`

## 1. 背景与目标

`packages/member-level-plugin` 已有完整的**积分获取侧**：订单送达按比例加积分（EARN）+ 成长值 + 等级，退款按比例扣积分（SPEND），积分明细 `MemberPointsHistory` 含 EARN/SPEND/ADJUST/EXPIRE 四类。但**消费侧断裂**：

- shop 端只有 `myMemberInfo` / `myPointsHistory` **查询**，没有任何积分消费入口 → 会员经济单向（只能赚不能花）
- 无 e2e 验证积分链路

本阶段目标：打通**积分抵现闭环**，让「赚分（送达）→ 花分（绑定订单抵现）→ 回流（取消/退款回退）→ 过期清理（EXPIRE）」形成可验证的完整会员经济链路。

## 2. 范围

### 2.1 目标（In Scope）
1. **积分抵现**：shop `redeemPoints(points)` 把用户积分绑定到当前订单 → Promotion 按积分折算折扣（复用原生结算机制）→ **绑定即扣积分**（SPEND 明细），防并发超花
2. **取消回退**：订单取消 → 按已抵扣积分回退（EARN 明细）+ 清空订单字段
3. **退款按比例回退**：Refund Settled → 按 `refund.total / order.total` 比例回退已抵扣积分
4. **拦截**：积分不足 / 非整数 / 未登录 / 折算金额为 0 或超订单总额
5. **过期清理**：定时任务按 EARN 明细 `expiresAt` 批量过期（幂等，扣余额 + EXPIRE 明细）
6. **e2e 全链路**：赚分 / 抵现 / 不足拦截 / 取消回退 / 退款回退 / 过期清理

### 2.2 非目标（Out of Scope）
- 积分 + 优惠券 / 拼团 / 秒杀 的叠加规则（仅保证同一订单 Promotion 各自独立生效）
- 积分明细分批次独立过期（仅按 EARN 明细整条过期）
- 等级权益差异化折扣（如金卡多抵 10%）
- 积分商城兑换实物（仅抵现）

## 3. 领域模型

### 3.1 Order 自定义字段（新增）
| 字段 | 类型 | 说明 |
|------|------|------|
| `pointsToRedeem` | int | 拟抵扣积分（绑定即扣后写入） |
| `pointsRedeemAmount` | int | 折算金额（分），结算 Promotion 据此折让 |

> `pointsRedeemed` 不再单独维护：**绑定即扣**，pointsToRedeem 即实际核销数，取消/退款按此回退。

### 3.2 Channel 自定义字段（新增）
| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `pointsPerYuan` | int | 100 | 多少积分抵 1 元（折算率，100 = 100 积分抵 1 元） |
| `pointsExpireDays` | int | 0 | 积分有效期（天），0=不过期 |

### 3.3 积分折算公式
```
discountAmount = min(floor(pointsToRedeem / pointsPerYuan) * 100, order.subTotal)
```
- `pointsPerYuan` 从 `ctx.channel.customFields` 读，未配置用默认 100
- 折扣为订单级折让（PromotionOrderAction），抵扣总额以订单 subTotal（不含运费）为上限

## 4. 核心机制

### 4.1 积分抵现（redeemPoints 绑定即扣）
```
redeemPoints(points)                              [shop, Authenticated]
  1. 校验：登录、订单存在、points 为正整数
  2. 折算：discountAmount = 按公式；<=0 或 >= subTotal → 拦截
  3. 余额：loadCustomerForUpdate 原子读 customer.points，< points → Insufficient points
  4. 扣减：customer.points -= points，写 SPEND 明细（orderId 关联，remark=points_redeem）
  5. 写订单字段：customFields.pointsToRedeem=points, pointsRedeemAmount=discountAmount
  6. 重算价格：applyPriceAdjustments → Promotion 按 state 折让
  7. 幂等：已绑定同一 activity 的订单直接返回（重复绑定提示或返回当前订单）
```

### 4.2 结算期动态折算
- 因**绑定即扣**策略，结算期无需再查用户余额/数据库：`pointsRedeemAmount` 已在绑定期折算并写入订单字段，Promotion 条件/动作**直接读订单字段**（比阶段12-14 更简，省去 runtime 注入）
- 条件 `points_redeem`（PromotionCondition）：
  - 读 `order.customFields.pointsToRedeem > 0` 且 `pointsRedeemAmount > 0` → 返回 `{ pointsToRedeem, pointsRedeemAmount }` 作 state
- 动作 `points_redeem_discount`（PromotionOrderAction）：
  - 读 state，返回 `-min(pointsRedeemAmount, order.subTotalWithTax)`（clamp 到当前 subTotal，订单内容变更后不超扣）
- 每张订单只需一张无参数促销「积分抵现」= points_redeem 条件 + points_redeem_discount 动作

### 4.3 取消回退
- `OrderStateTransitionEvent → Cancelled`：若 `order.customFields.pointsToRedeem > 0` → 回退该积分（EARN 明细，remark=order_cancelled）→ 清空 pointsToRedeem/pointsRedeemAmount
- 幂等：回退前检查该订单是否已有对应 EARN 明细（remark=`order_cancelled:<orderId>` 或按 orderId+type 判重）

### 4.4 退款按比例回退
- `RefundStateTransitionEvent → Settled`：若订单 pointsToRedeem > 0，按 `floor(pointsToRedeem × refund.total / order.total)` 回退积分（EARN 明细，remark=`refund_settled:<refundId>`）
- 幂等：按 orderId + type=EARN + remark 前缀判重，防同订单多笔退款重复回退

### 4.5 过期清理（scheduled task）
- 条件：`pointsExpireDays > 0`
- 任务扫描 `MemberPointsHistory` 中 `type=EARN AND expiresAt != null AND expiresAt < now` 且**未过期处理**的明细
- 对每条：幂等判重（已有 EXPIRE 明细 remark=`earn_expired:<earnId>` 则跳过）→ `loadCustomerForUpdate` 原子扣减余额 → 写 EXPIRE 明细（amount=-该笔金额，remark=`earn_expired:<earnId>`）
- 积分获取时写入 expiresAt：`handleOrderDelivered` 调 addPoints 时带 `expiresAt = now + pointsExpireDays`

## 5. 状态机/事件接线

| 事件 | 动作 |
|------|------|
| `OrderStateTransitionEvent → Delivered` | 加积分 + 成长值（现有，新增 expiresAt 落库） |
| `OrderStateTransitionEvent → Cancelled` | 回退已抵扣积分 + 清订单字段 |
| `RefundStateTransitionEvent → Settled` | 按比例回退已抵扣积分 |
| ScheduledTask（每 5 分钟） | 扫描过期 EARN 明细 → 扣余额 + EXPIRE 明细 |

## 6. e2e 场景（全链路 8 用例）

1. 插件可加载；初始无抵现订单字段
2. 赚分：订单送达 → 积分/成长值按比例增加，SPEND 明细生成，expiresAt 落库
3. 抵现成功：redeemPoints → 折扣金额生效 → subTotalWithTax 落到抵扣后
4. 不足拦截：redeemPoints > 余额 → Insufficient points
5. 折算上限拦截：折算金额 >= subTotal → 拦截
6. 取消回退：抵现后取消订单 → 积分全额回退（EARN 明细）+ 订单字段清空
7. 退款回退：支付→送达→退款 → 积分按比例回退
8. 过期清理：EARN 明细 expiresAt 已过 → 定时任务扣余额 + EXPIRE 明细（幂等）

# 阶段22 · 实施计划（结算/下单时运费计算 + 范围联动）

依据：`2026-08-21-本地电商就近履约阶段22设计-结算运费计算范围联动.md`

核心：在既有 `@vendure/address-plugin` 内扩展——`DeliveryRange` 加 `baseFee/freeThreshold`；`RangeShippingEligibilityChecker`（结算拦截）+ `RangeShippingCalculator`（按店运费）注册进 `config.shippingOptions`；Order 侧 custom fields 承载收件区码/经纬度；C 端 `setOrderShippingFromAddress` + `activeOrderDeliveryStatus`（加购预检）。

## 执行顺序

### Step 1 — 实体扩展 `delivery-range.entity.ts`
- `DeliveryRange` 增列：`@Column({ type: 'int', default: 0 }) baseFee`；`@Column({ type: 'int', nullable: true }) freeThreshold`（null=不包邮）。
- 不动 Date/pit 铁律相关列；跨库 SQL 列安全。

### Step 2 — 服务扩展 `delivery.service.ts`
- `getOrderShopIds(ctx, order)`：`order.lines` 去重 productId → 查 `Product.shopId`（shop-plugin 自定义字段）→ number[]（repository 直接取，避免跨包 DI 环）。
- `computeShopSubtotal(order)`：按 product→shopId 分组，`order.lines` 金额求和（用 `line.linePriceWithTax`，核心依据）。
- `getRange`/`upsertRange` 增加 baseFee/freeThreshold 写入（`input.baseFee/freeThreshold !== undefined` 时赋值）。
- 复用 `validateDelivery` 供 checker/预检消费。

### Step 3 — 运费计算 `range-shipping-calculator.ts`
- `RangeShippingCalculator`（Vendure `ShippingCalculator`）：`calculate(ctx, order, args)` → per shop fee（小计≥freeThreshold ⇒0 else baseFee），Σ 为 price；`priceIncludesTax` 取 `order.channel`/`ctx` 口径；`taxRate: 0`；返回 `metadata.shops`。
- `languageCode`/`` 字段对齐 core 签名，缺省 `minimumValue` 用 0。

### Step 4 — 结算拦截 `range-shipping-eligibility-checker.ts`
- `RangeShippingEligibilityChecker`（Vendure `ShippingEligibilityChecker`）：`check(ctx, order)` —— 地址未设→true；否则用 Order custom fields（区码/经纬度）构造地址，`validateDelivery` 逐店，任一 false→返回 false。
- `shouldRunCheck` 缺省 true。

### Step 5 — Order custom fields + 插件注册 `plugin.ts`
- `src/order-custom-fields.ts`：Order 上注册 `shippingLng/Lat/provinceCode/cityCode/districtCode`（nullable）。
- `plugin.ts`：
  - `entities/providers` 不变（复用 DeliveryRange/DeliveryService）。
  - `configuration: (config) => ({ ...config, customFields: { ...config.customFields, Order: [...(config.customFields.Order ?? []), ...orderCustomFields] }, shippingOptions: { ...(config.shippingOptions ?? {}), shippingEligibilityCheckers: [...(config.shippingOptions?.shippingEligibilityCheckers ?? []), rangeShippingEligibilityChecker], shippingCalculators: [...(config.shippingOptions?.shippingCalculators ?? []), rangeShippingCalculator] } })`（仿 logistics-plugin 注册方式）。
  - adminSchema 的 `DeliveryRange`/`DeliveryRangeInput` 与 shopSchema `DeliveryRange` 增 `baseFee/freeThreshold`。

### Step 6 — C 端 resolver `delivery-shop.resolver.ts`
- `setOrderShippingFromAddress(deliveryAddressId)`：取地址 → `OrderService`（经 Injectable 注入 `OrderService`）写 `shippingAddress` + 存 Order custom fields；需把 OrderService 加为 provider 依赖（address-plugin 已有 core 依赖面）。
- `activeOrderDeliveryStatus`：active order → `validateDelivery` 逐店 → `{ deliverable, results: [{shopId,inRange,reason}] }`。

### Step 7 — e2e `e2e/address.e2e-spec.ts`（≥12 用例，见设计 §9）
- 准备：admin 建 shopA/B + `assignProductsToShop` 两个商品并分别归属；admin 建 ShippingMethod（用 range checker+calculator code）；顾客登录、`setOrderShippingFromAddress`。
- 覆盖：persist baseFee/freeThreshold / 单店求和 / 包邮 / 不包邮 / 多店混合 / 结算 eligible 拦截+放行 / 地址未设跳过 / activeOrderDeliveryStatus / circle 距离联动 / metadata 明细 / 空订单防御。
- 运行：`packages/address-plugin` 内 `$env:PACKAGE='address-plugin'; npx vitest run --config vitest.config.mts e2e/address.e2e-spec.ts`；改实体删 `e2e/__data__/*.sqlite`。

### Step 8 — 构建

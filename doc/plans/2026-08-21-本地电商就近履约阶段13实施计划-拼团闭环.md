## 2. 实施步骤

### Step 1: group-buy-runtime.ts（新增）
```ts
import { TransactionalConnection } from '@vendure/core';
let connection: TransactionalConnection | undefined;
export function setGroupBuyConnection(conn: TransactionalConnection): void { connection = conn; }
export function getGroupBuyConnection(): TransactionalConnection {
    if (!connection) throw new Error('GroupBuyPlugin TransactionalConnection not initialized');
    return connection;
}
```

### Step 2: group-buy-promotion-condition.ts（重写）
- `check`（async）：读 `order.customFields.groupBuyActivityId` → 运行时查活动 → 校验：
  - 活动存在
  - status 非 expired；非 active 且 !allowJoinAfterComplete → false
  - 窗口：startAt ≤ now ≤ endAt
  - 订单包含拼团变体行（`lines[].productVariant.id === activity.variantId`）
- 通过返回 `{ activityId, variantId: activity.variantId, groupPrice: activity.groupPrice }`
- `priorityValue: 900`

### Step 3: group-buy-price-action.ts（重写）
- `PromotionItemAction`，`conditions: [groupBuyDiscountCondition]`
- `execute(ctx, orderLine, _args, state)`（async）：
  - `const s = state.group_buy_discount`；无 `groupPrice` → 0
  - `orderLine.productVariant?.id !== String(s.variantId)` → 0
  - `unitPrice = pricesIncludeTax ? orderLine.unitPriceWithTax : orderLine.unitPrice`
  - `delta = unitPrice - groupPrice`；`delta > 0 ? -delta : 0`

### Step 4: group-buy-leader-promotion.ts（重写）
- `check`（async）：`customFields.groupBuyIsLeader === true && groupBuyActivityId` → 查活动 → `leaderRewardType === 'discount' && leaderDiscount > 0` → 返回 `{ variantId, leaderDiscount }`
- `priorityValue: 890`

### Step 5: group-buy-leader-reward-action.ts（重写）
- 读 `state.group_buy_leader_reward`；命中变体行 → `-leaderDiscount`

### Step 6: group-buy.service.ts（修改）
`init(injector)` 增加：
```ts
setGroupBuyConnection(this.connection);
```
`joinGroupBuy(ctx, activityId, orderId, isLeader)` 重写：
1. 加载 order（`findOne(ctx, orderId, ['customer','customer.user','lines','lines.productVariant'])`）
2. 归属校验：`order.customer.user.id === ctx.activeUserId`（勿用 customer.id）
3. 加载活动；校验存在、status（非 expired；completed 且 !allowJoinAfterComplete → 拒绝）、窗口
4. 幂等检查：已存在 `GroupBuyOrder(orderId)` → 仅更新 isLeader + 订单字段，不递增
5. 校验订单含拼团变体行
6. 原子递增（防超员）：受影响=0 → 抛 `Activity is already full or not joinable`
7. `orderService.updateCustomFields(ctx, orderId, { groupBuyActivityId: Number(activityId), groupBuyIsLeader: isLeader })` + `applyPriceAdjustments`
8. upsert `GroupBuyOrder`（新：status = 活动已完成? 'success' : 'pending'）
9. 重读活动；`currentCount >= targetCount && status==='active'` → 置 completed + 该活动 pending 记录置 success

新增 `applyExpiryCheck(ctx): Promise<void>`：迁移 `GroupBuyJob.runCheck` 的过期清理核心（取消+退款+failed），供定时任务与手动 mutation 共用（保留 job 内的幂等）。

### Step 7: plugin.ts（修改）
- `onApplicationBootstrap`：调 `this.groupBuyService.init(this.injector)` 已存在（init 内会 setGroupBuyConnection）
- admin schema：新增 `runGroupBuyExpiryCheck: Boolean!` mutation
- admin resolver：注入 `GroupBuyJob`（或 Service），转发调用

### Step 8: e2e（重写）
- 复用 coupon e2e 的初始化模式：`customerCount: 2`、`testSuccessfulPaymentMethod`、`pricesIncludeTax: true`
- 创建两张 Promotion（拼团价 + 团长折扣），condition/action 无参数
- 场景：见设计 §7（6 个用例）
- 过期场景：join+支付后，admin `updateGroupBuyActivity(endAt=过去)` → `runGroupBuyExpiryCheck` → 断言活动 expired / 订单 Cancelled / Refund Settled / 参团记录 failed

# 阶段47 实施计划：店主自营后台 · 库存能力

> 目标：承接阶段18「店主自营后台账权体系」边界第5条**店主不开放库存**缺口，为店主补上**投射到自营后台（ADMIN API）的库存能力**——只读水位 + 归属校验下的库存调整。
> 现状：店主结算（账单/明细/提现 `myAccount`/`mySettlementEntries`/`myWithdrawalRequests`/`requestWithdrawal`）已由 **settlement-plugin**（阶段24）实现并均 `@Allow(manageOwnShop.Permission)` + `requireMyShop` 隔离；店主店铺/商品/订单/评价已由 **shop-plugin**（阶段17/18）实现。**库存域目前仅有平台权限（`ViewStock`/`ManageStockIn` 等），店主无任何库存入口。**

## 1. 范围与验收

### A. 店主库存只读水位 `myShopStock`
- 店主在自营后台查询**本人店铺商品**的逐仓库存水位（含可售/占用）。
- 数据口径：`Product.customFields.shopId === 我的 shop.id` 的商品 → 其全部 variant → 逐 `StockLocation` 取 `StockLevel`（stockOnHand/stockAllocated/stockAvailable），按商品/变体/位置聚合。
- **归属隔离**：只返回我店商品，绝不泄他人店铺商品。位置为平台仓库资源，仅投影可见不校验店主对位置的权限。
- GraphQL：`myShopStock(productId: ID): [MerchantVariantStock!]!`（逐位置 `{ locationId locationName stockOnHand stockAllocated stockAvailable }`）。
- **验收**：店主的商品在各仓有水位；店主 B 查不到店主 A 的商品水位。

### B. 店主库存调整 `myShopStockAdjust`
- 店主对**本人店铺商品**的某 variant 在某位置做**绝对量校准**（等价平台 `setVariantStock`，delta=目标-当前），写 **`manual`** 账本便于追溯。
- **归属隔离**：先校验 variant 所属商品 `shopId === 我的店`，非本店商品抛 Forbidden；再执行 `adjustStockForLocation`（复用 inventory 账本封装）。
- GraphQL：`myShopStockAdjust(variantId: ID!, stockLocationId: ID!, stockOnHand: Int!): Boolean!`。
- **验收**：调整后该位置水位变化且 `stockLedger(bizType=manual, bizCode=myShop-)` 有记录；调他人店铺商品被拒。

### C. 权限与归属
- 全部店主库存能力 `@Allow(manageOwnShop.Permission)`（复用 shop-plugin 导出的 `manageOwnShop` `PermissionDefinition`），归属由 service `requireMyShop(ctx)` 二次把关。
- 放在 **inventory-plugin** 新增 `inventory-merchant.resolver` / service 方法（保持库存逻辑归属 inventory-plugin，权限引用 `@vendure/shop-plugin` 的 `manageOwnShop` + `requireMyShop` 语义；库存 service 自实现 `requireMyShop` 或以 shop-service 为 peer 依赖注入）。

### D. e2e 用例
| # | 用例 | 断言要点 |
|---|---|---|
| 1 | 插件可加载；非店主管理员调店主库存被 Forbidden | 平台 admin 无 manageOwnShop → 拒绝 |
| 2 | 开店+开通店主账号（复用 shop 流程 provisionShopOwner） | administratorId 绑定 |
| 3 | 店主只读水位：myShopStock 返回本人商品逐仓水位 | 值=StockLevel；不含他人商品 |
| 4 | 店主调整库存：myShopStockAdjust 改水位 + 写 manual 账本 | 水位变化 + ledger 记录 |
| 5 | 归属隔离：店主调/读他人店铺商品被 Forbidden/空结果 | 403 / 空 |

## 3. 非目标（边界）与后续
- **不做屏幕店主 dashboard UI**（店主自营后台前端不在本阶段；仅补 ADMIN GraphQL 能力，后续由前端 C 端/后台页面消费）。
- 不做店主**采购补货**（阶段46 Supplier/PurchaseOrder 为平台域；店主主动下单补货留后续）。
- 不做店主库存**盘点/调拨**单据（仅绝对量校准手动调库；盘点/调拨为平台域）。
- 不做店主默认库存位置绑定（位置是平台资源，店主按 stockLocationId 显式传参）。
- **店主结算已具备**（settlement-plugin `my*`），不在本阶段重复。

## 4. 依赖就绪说明
- `manageOwnShop` 权限：`@vendure/shop-plugin` 已导出（merchant-resolver 使用），库存 resolver 引用之即与店主域同权。
- 归属解析 `requireMyShop(ctx)`：为保持 inventory 不反向注入 shop-service，本阶段在 inventory 内以**同口径 service**实现（activeUserId→Administrator→Shop.administratorId），或 peer 依赖注入 shop-plugin 的 Service —— 实施时择优（倾向 peer 依赖注入，避免口径漂移）。
- 账本封装 `adjustStockForLocation` 已支持 `bizType:'manual'`（阶段11+ 沉淀），店主校准零新增账本逻辑。

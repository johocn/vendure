# 阶段49 实施计划：店主订单履约

> 目标：补齐店主自营后台的「订单履约」能力 —— 店主对本人店铺订单行发货（创建 Fulfillment 并流转至 Shipped）、查看本人店铺行的发货单与履约进度。
> 归属：复用 shop-plugin `manageOwnShop` 权限 + `requireMyShop`；订单行归属隔离到「该单中 productVariant.product.customFields.shopId === 本店」的行。

## 背景与现状
- 订单聚合已存在：`aggregateMerchantOrders`（阶段18）按我店行聚合 `myShopOrders / myShopOrder`（只含我店行，不泄露他人店铺行）。
- 核心履约能力（Vendure core）：
  - `OrderService.createFulfillment(ctx, { handler, method, trackingCode, lines: OrderLineInput[] })`：可对**任意行子集**创建 Fulfillment，自动 `Created→Pending`（并产生 Sale 库存移动）。handler 默认 `manual-fulfillment`。
  - `OrderService.transitionFulfillmentToState(ctx, id, state)`：Pending→Shipped 等。
  - Fulfillment 状态：Created→Pending→Shipped→Delivered（delivery-plugin 负责后续 Shipped→Delivered）。
- 缺口：店主无「发货」入口，也无「履约进度/发货单」查看。

## 交付范围（A~C）

### A. 店主发货 `fulfillMyShopOrder`
- `ShopService.fulfillMyShopOrder(ctx, orderId, method?, trackingCode?): FulfillMyShopOrderResult`
  1. `requireMyShop`
  2. 取订单 + `lines.productVariant.product`，滤出本店行；算每行已履约量（非 Cancelled FulfillmentLine 求和）与剩余量。
  3. 若全部已履约 → 返回 noway（剩余 0，直接返回摘要，不发重复货）。
  4. `orderService.createFulfillment`（manual-fulfillment，行=本店未履约行+各自剩余量）→ Fulfillment(Pending)。
  5. `orderService.transitionFulfillmentToState(ctx, id, 'Shipped')`。
  6. 返回摘要：orderId / totalItemCount / shippedItemCount / remainingItemCount / fulfillmentIds。

### B. 履约查看 `myShopOrderFulfillments`
- `ShopService.getMyShopOrderFulfillments(ctx, orderId): MerchantFulfillment[]`
  - 本店行 → FulfillmentLine（state!=Cancelled）按 fulfillment 归组：id/state/method/trackingCode/createdAt/items(行明细)。
- `MerchantFulfillment` 类型 + admin schema query。

### C. 列表增强
- `MerchantOrderLine` 增加 `fulfilledQuantity: number`，`aggregateMerchantOrders` 查询 FulfillmentLine 回填，让店主订单列表显示已发/待发。

## 构建与部署（铁律）
本地构建 shop-plugin `lib/` 提交入库；服务器仅 `git pull + pm2 restart`。

## e2e（shop-service / merchant e2e 扩展）
老验：店主 A 对本人店铺下单支付后：fulfillMyShopOrder 返回摘要、fulfillment 状态 Pending→Shipped、列表 fulfilledQuantity 回填；越权（他人店铺行 / 无发货权）被拒；重复发货不再新增。

## 约束
- 不注入它店数据：货集合只含本店行。
- 复用 core fulfillment（不重写状态机），仅包一层店主归属/行隔离。

# 本地电商就近履约 · 阶段31设计：会员签到/任务体系

> 目标：让会员在 C 端通过「每日签到 + 任务中心」持续获得成长值与积分，喂给阶段30的 MemberTier 等级权益体系。本插件只负责**产出**成长值/积分，不重复造等级逻辑。

## 背景与定位

阶段30 已把成员从「标签」升级为 `MemberTier` 表驱动的权益体系（积分倍率/抵现/免运费/专属折扣）。但成长值与积分的**获取回路**还很单薄（仅下单 Delivered 产生）。本阶段补齐运营侧的增长玩法：用户每日签到、完任务，换取成长值（升级）与积分（消费/抵现）。

**衔接方式**：跨插件注入 `@vendure/member-level-plugin`（lib）的 `MemberLevelService`，调用：
- `addGrowthValue(ctx, customerId, amount, source?)` —— 成长值增减，内部自动联动 `memberLevel` 与 `resolveTierForGrowth`
- `addPoints(ctx, customerId, amount, orderId?, remark?, expiresAt?)` —— 增加 EARN 积分（含过期）
- `adjustPoints(ctx, customerId, amount, remark?)` —— 运营调整

所有发奖统一走这两个入口，remark 按 `checkin:<date>` / `task:<taskCode>` 记录，与既有积分账本一致。

## 架构总览

新建独立插件 `packages/checkin-plugin`（四件套脚手架 + lib 本地重建入库，部署铁律不变）。

- **实体**：`CheckinRecord`（每日签到）、`TaskRecord`（任务完成记录），均 ChannelAware（`channelId` 普通列 NOT NULL + `@ManyToMany(Channel)`）。
- **渠道配置**：在 Channel 上注册约 26 个 int 自定义字段（奖励值），缺省取插件 `init(options)` 的默认值（对齐 `pointsEarnRatio` 既有风格，避免硬编码）。
- **任务目录**：固定清单（三个 repeatability 类型），satisfaction触发途径分「主动领奖」与「订单事件自动发奖」两种。
- **事件驱动**：订阅 `OrderStateTransitionEvent → Delivered`，重载订单后累计该顾客单数/消费额，命中里程碑阈值即自动发奖（幂等）。

## 数据模型

### CheckinRecord（每日签到）
| 列 | 类型 | 说明 |
|---|---|---|
| id | int PK | VendureEntity |
| channelId | int NOT NULL | 渠道（对齐 MemberTier） |
| customerId | int NOT NULL | 顾客 |
| checkinDate | varchar(10) | `YYYY-MM-DD`，本地时区 |
| points | int | 本次签到获得积分 |
| growth | int | 本次签到获得成长值 |
| streak | int | 结算时的连续签到天数 |
| createdAt | Date 可选 | 签到时间 |

唯一/幂等：`@Index(['customerId','checkinDate','channelId'], { unique: true })` → 同顾客同渠道同一天只能签一次。

连续天数 `streak`：在签到结算时按「上一条签到记录日期」计算——等于 `昨日` 则 `streak=昨日.streak+1`，否则断签归 `1`。不依赖任务调度清零，天然抗漏签。

### TaskRecord（任务完成记录）
| 列 | 类型 | 说明 |
|---|---|---|
| id | int PK | VendureEntity |
| channelId | int NOT NULL | 渠道 |
| customerId | int NOT NULL | 顾客 |
| taskCode | varchar | 任务标识（如 `daily_share`） |
| type | varchar | `CHECKIN`/`MILESTONE`/`ACCOUNT` |
| repeatability | varchar | `DAILY`/`ONCE` |
| period | varchar(10) nullable | DAILY 任务落 `YYYY-MM-DD`；ONCE 任务空 |
| points | int | 实发积分 |
| growth | int | 实发成长值 |
| completedAt | Date 可选 | 完成时间 |

幂等：`@Index(['customerId','taskCode','channelId','period'], { unique: true })`
- DAILY 任务：period=当天日期，同天不可重复
- ONCE 任务：period=NULL，终身一次

（`type`/`repeatability` 用 varchar 列避免字符串联合类型反射成 Object —— 阶段12/27 铁律。）

## 任务目录（固定）

### 每日签到类 —— `type=CHECKIN`，`repeatability=DAILY`，C 端点「签到」主动领
| taskCode | 说明 |
|---|---|
| `daily_checkin` | 每日签到（主签到按钮，写 `CheckinRecord`，含连续奖励） |

> 说明：签到走独立 `CheckinRecord` 实体而非 `TaskRecord`（因为带 streak 结算和连续奖励），但对外抽象也作为「每日任务」之一。另两类「分享/登录/完善资料」在阶段31先收敛为下面的 ACCOUNT 主动项，避免任务清单过度膨胀。

### 账户成长 —— `type=ACCOUNT`：`DAILY` 主动领 / `ONCE` 领
| taskCode | repeatability | 触发 |
|---|---|---|
| `daily_share` | DAILY | C 端点「分享」主动领 |
| `daily_login` | DAILY | C 端点「登录签到」主动领 |
| `daily_profile` | DAILY | C 端点「完善资料」主动领 |
| `bind_phone` | ONCE | 已绑定手机号，可主动领 |
| `reach_level` | ONCE | `memberLevel>=阈值`，可主动领（服务端校验） |

### 订单里程碑 —— `type=MILESTONE`，`repeatability=ONCE`，订单 Delivered 事件自动发奖
| taskCode | 条件 |
|---|---|
| `first_order` | 累计完成 **1** 单即发 |
| `order_count` | 累计完成单数 ≥ `orderCountThreshold` 发 |
| `order_amount` | 累计消费金额（含税总额）≥ `orderAmountThreshold`（分）发 |

里程碑**无需 C 端领奖**：插件订阅 `OrderStateTransitionEvent(filter toState==='Delivered')`，重载订单的 customer 后，按该顾客累计 `Order{state∈终态交付集合}` 计算单数与含税消费额，命中阈值 → 写 `TaskRecord` + 调 `MemberLevelService` 发奖。

## 渠道自定义字段（int，默认取 options）

| 字段 | options 默认 | 含义 |
|---|---|---|
| `checkinPoints` | 10 | 每日签到基础积分 |
| `checkinGrowth` | 10 | 每日签到基础成长值 |
| `checkinStreakThreshold` | 7 | 连续满 N 天触发额外奖励（0=关闭） |
| `checkinStreakBonusPoints` | 50 | 连续满阈值当天额外积分 |
| `checkinStreakBonusGrowth` | 50 | 连续满阈值当天额外成长值 |
| `taskSharePoints` / `taskShareGrowth` | 20/20 | 每日分享 |
| `taskLoginPoints` / `taskLoginGrowth` | 5/5 | 每日登录 |
| `taskProfilePoints` / `taskProfileGrowth` | 30/30 | 每日完善资料 |
| `taskBindPhonePoints` / `taskBindPhoneGrowth` | 50/50 | 绑定手机（ONCE） |
| `taskReachLevelThreshold` | 3 | 达到该等级（ONCE） |
| `taskReachLevelPoints` / `taskReachLevelGrowth` | 100/100 | 达到等级奖励 |
| `taskFirstOrderPoints` / `taskFirstOrderGrowth` | 200/200 | 首单（ONCE） |
| `taskOrderCountThreshold` | 5 | 累计 N 单里程碑 |
| `taskOrderCountPoints` / `taskOrderCountGrowth` | 500/500 | 累计单数奖励 |
| `taskOrderAmountThreshold` | 50000 | 累计满 N 分（500元） |
| `taskOrderAmountPoints` / `taskOrderAmountGrowth` | 1000/1000 | 满额奖励 |

默认值集中在 `CheckinPluginOptions` 的结构体 `defaultRewards` 中，渠道字段为覆盖层（读取顺序：channel customFields 非空则用 → 否则 options 默认 → 否则内在兜底）。

## shop-api / admin-api

### shop-api（C 端，`@Allow(Permission.Authenticated)` + `requireCustomer`）
- `checkin: CheckinResult` —— 今日签到。幂等：同渠道同日已签则返回 `{ success:false, reason:already }` 不重复发奖；首次签则结算积分/成长/连续奖励。
- `checkinToday: CheckinTodayInfo` —— `{ checkedIn:boolean, streak, canCheckin:boolean }`。
- `myTasks: [TaskSummary]` —— 任务列表 + 每个任务的 `state`（`available|claimed|not_met`）+ 进度提示。
- `claimTask(taskCode): RewardResult` —— 主动领「每日签到类 + 账户成长」；重复领（同 DAILY 同日 / ONCE 已领）返回 `{ success:false, reason:already }`。

### admin-api
- 奖励配置：经标准 `updateChannel` 改本插件注册的 channel 字段即可，**无需新 mutation**（对齐 member-level 渠道字段风格）。
- 统计/留存看板本阶段不做（YAGNI），留待运营数据看板阶段。

## 数据流与幂等（核心防重）

1. **签到/主动任务**：`claimTask`/`checkin` 里先按幂等键 `findOne`，存在→返回 already；不存在→用 `getRepository` 插入记录 + 在**同一事务**内调 `MemberLevelService.addGrowthValue/addPoints`（或 `adjustPoints` 记 remark）。唯一键兜底并发二次插入（sqljs `SELECT,INSERT` 竞态由唯一索引防护，冲突抛错→吞掉并返回 already）。
2. **事件里程碑**：`handleOrderDelivered` 重载订单 customer 与全部行，算该顾客累计（count + 含税金额合计）。对每个里程碑任务：幂等键命中已存在 → 跳过；否则发奖+写记录。事件重放/重复 Delivered → 不重复发。
3. **成长值联动**：`addGrowthValue` 内部会重查 tier 刷新 `memberLevel`，无需本插件关心。积分数额由各任务单独配置。

## 错误处理

- 未登录/无顾客 → `UnauthorizedError` / `EntityNotFoundError`（复用 member/review 口径）。
- 主动任务未满足条件（如 `reach_level` 未达阈值 / `bind_phone` 未绑）→ 返回 `not_met`，不写记录不发奖。
- 里程碑查询读不到订单关系 → 用 `orderService.findOne(id,[customer, lines, ...])` 重载（阶段10/15 铁律），勿直接用事件 order。

## 测试策略

`e2e/checkin.e2e-spec.ts`，装配 `MemberLevelPlugin` + `CheckinPlugin`（checkin 依赖 member-level 发奖），单测分离：
- 签到幂等（同日两次只发一次）、断签 streak 重置、连满阈值额外奖励
- 每日任务主动领 + 同日拦截、ONCE 任务终身一次、未达条件返回 not_met
- 事件里程碑：首单/累计单数/累计满额在 Delivered 自动发奖；同单重放不重复发
- 渠道隔离：新渠道独立记录与配置
- 积分/成长值到账联动 `MemberLevelService.getMyMemberInfo` 断言

**改实体 schema 后删 `e2e/__data__/*.sqlite` 重跑。运行在插件目录内**：`$env:PACKAGE='checkin-plugin'; npx vitest run --config vitest.config.mts e2e/checkin.e2e-spec.ts`。

# 阶段21 · 收货地址 + 按店配送范围 设计

## 目标
补齐「就近履约」的地理能力：
1. **C 端收货地址簿**：顾客维护多个中国化收货地址（省市区 + 详细地址 + 经纬度 + 默认标记），下单前选址。
2. **按店配送范围**：每个商家（`Shop`）配置自己的配送范围（圆心半径 / 省市区白名单 / 不限），C 端结算前按购物车中涉及的店铺逐一校验收货地址是否可配送（任一店不可达 → 整单不可达）。

边界外（后续阶段）：不做把校验嵌入 `activeOrder` 结算闸门（addPaymentToOrder 前强制拦截）、不做配送运距计费、不做地图选点 SDK 接入（坐标由前端地图组件采集传入）。

## 新插件 `delivery-plugin`

### 实体

#### DeliveryAddress（C端收货地址簿）
| 列 | 类型 | 说明 |
|---|---|---|
| id | PK | VendureEntity |
| customerId | int NOT NULL | 归属顾客（data 隔离） |
| fullName | varchar NOT NULL | 收货人 |
| phone | varchar NOT NULL | 手机号 |
| province/city/district | varchar NULL | 省/市/区 名称 |
| provinceCode/cityCode/districtCode | varchar NULL | 行政区划编码（省市区白名单校验用） |
| detail | varchar NULL | 详细地址（街道/门牌） |
| lng/lat | float NULL | 经纬度（circle 校验用） |
| isDefault | boolean default false | 是否默认（同顾客最多一条） |
| channelId | int NOT NULL | 渠道隔离（ChannelAware，对齐铁律） |

- `@Index(['customerId','isDefault'])`。

#### DeliveryRange（商家配送范围，一店一档）
| 列 | 类型 | 说明 |
|---|---|---|
| id | PK | |
| shopId | int NOT NULL | 关联 shop-plugin `Shop` |
| enabled | boolean default false | 是否开通配送；false=不配送 |
| rangeType | varchar NOT NULL default 'all' | `all` 不限 / `circle` 圆心半径 / `district` 省市区白名单 |
| centerLng/centerLat | float NULL | circle：圆心 |
| radiusKm | float NULL | circle：半径(km) |
| districtCodes | varchar NULL | district：白名单编码 JSON 数组文本（跨库安全，服务内 JSON.parse） |
| channelId | int NOT NULL | 渠道隔离 |

- `@Index(['shopId','channelId'], { unique: true })` 每店每渠道一档（conver to upsert 幂等）。

### 服务 delivery.service.ts
- 注入 `TransactionalConnection`、`CustomerService`（requireCustomer）、`Logger`。
- `requireCustomer(ctx)`：activeUserId 空→Unauthorized、无顾客→NotFound（对齐 review 口径）。
- 地址簿（均按 `customerId = requireCustomer.id` 过滤，data 隔离）：
  - `listMyAddresses` / `createAddress`（首个地址自动 isDefault） / `updateAddress` / `deleteAddress` / `setDefaultAddress`（事务里先 reset 本顾客全部 isDefault=false 再置目标 true）。
- 配送范围（admin，`@Allow(Permission.UpdateSettings)`，平台运营按店配置）：
  - `getRange(ctx, shopId)` / `upsertRange(ctx, input)`（按 `shopId+channelId` 判存在则 update 否则 insert，幂等）。
- 校验：
  - `validateDelivery(ctx, { address, shopIds })` → `DeliveryResult[]`：逐店取 range：
    - range 不存在 / `!enabled` → `{ inRange:false, reason:'NO_DELIVERY' }`
    - `rangeType='all'` → `{ inRange:true, reason:'OK' }`
    - `rangeType='circle'`：需地址有 lat/lng，`haversineKm(center, addr) <= radiusKm` → true else `{false,'BEYOND_RANGE'}`；无坐标 → `{false,'NO_COORDINATES'}`
    - `rangeType='district'`：地址的 `[districtCode,cityCode,provinceCode]` 任一 ∈ 白名单 → true else `{false,'NOT_IN_RANGE'}`
- 地理工具 `haversineKm(lat1,lng1,lat2,lng2)`（大地距离，km）。

### API
#### Shop API
- 地址簿（`@Allow(Permission.Authenticated)`）：
  - `myDeliveryAddresses: [DeliveryAddress!]!`
  - `createDeliveryAddress(input: DeliveryAddressInput!): DeliveryAddress!`
  - `updateDeliveryAddress(id: ID!, input: DeliveryAddressInput!): DeliveryAddress!`
  - `deleteDeliveryAddress(id: ID!): Boolean!`
  - `setDefaultDeliveryAddress(id: ID!): [DeliveryAddress!]!`（返回最新列表，便于前端刷新默认态）
- 配送范围（`@Allow(Permission.Public)`，结算前可见）：
  - `shopDeliveryRange(shopId: ID!): DeliveryRange`
  - `validateDelivery(input: ValidateDeliveryInput!): [DeliveryResult!]!`
    - `ValidateDeliveryInput { address: DeliveryAddressInput!, shopIds: [ID!]! }`
    - `DeliveryResult { shopId: ID!, inRange: Boolean!, reason: String! }`

#### Admin API（`@Allow(Permission.UpdateSettings)`）
- `deliveryRange(shopId: ID!): DeliveryRange`
- `upsertDeliveryRange(input: DeliveryRangeInput!): DeliveryRange!`

Input：
- `DeliveryAddressInput { fullName!, phone!, province?, city?, district?, provinceCode?, cityCode?, districtCode?, detail?, lng?, lat? }`
- `DeliveryRangeInput { shopId!, enabled?, rangeType?, centerLng?, centerLat?, radiusKm?, districtCodes?: [String!] }`

### 安全 / 隔离
- 地址簿强隔离：service 内一律 `customerId: requireCustomer.id`；越权改/删他人地址 → `EntityNotFoundError`。
- 范围配置 admin 侧 `UpdateSettings`；C 端读取 `Public`（范围本就应公开供校验）。
- 渠道隔离：地址/范围均按 `ctx.channelId` 过滤。

### 依赖
- peer `@vendure/core`（Product/Asset/RequestContext/TransactionalConnection/CustomerService）。
- 复用 shop-plugin `Shop` 实体（lib 引用，repository 直接取，避免注入其 service 的 DI 环）。
- e2e plugins：`DeliveryPlugin.init()` + ShopPlugin（供 Shop 实体与建店数据）。

### 性能
- 校验为轻量内存计算（每店读一条 range + haversine/白名单），无 N+1 风险，不缓存。

### 构建/部署
- lib 本地 `tsc` 构建入库；服务器 `git pull + pm2 restart`（部署铁律）。

# 阶段33 设计 · 会员储值余额钱包（Member Balance Wallet）

> 日期：2026-08-21
> 关联实施计划：`2026-08-21-本地电商就近履约阶段33实施计划-会员储值余额钱包.md`
> 前置：阶段32（预售/定金预售）已完成；余额钱包基础组件已存在于 `recharge-card-plugin`
> 落地：**扩展** `packages/recharge-card-plugin`（不复刻、不新建包）

## 0. 结论摘要

本阶段在现有 `@vendure/recharge-card-plugin` 的**余额钱包基础**上补齐能力，使其成为完整的「会员储值余额钱包」：

1. **关键前置修复 —— customerId 口径统一**（现有 bug）：余额的消费/充值落库用 `ctx.activeUserId`（登录 User.id），退款却用 `order.customer.id`（Customer.id），**两套键混用**导致同一账户余额可能分裂、退款贷不到扣款行。统一改为 `customer.id`（经 `customerService.findOneByUserId` 解析），所有余额入口口服一致。
2. 新增 `RechargeOrder`（充值单，预留网关口）。
3. admin 手工调整余额（含冲正幂等）。
4. 统一资金流水查询（充值/消费/退款/调整/冻结）。
5. 余额支付/退款增强（防重复扣减、退款不超该单消费）。
6. e2e 覆盖 + 回归现有卡密兑充。

## 1. 现状核实（裁决依据）

| 项 | 结论 | 来源 |
|---|---|---|
| `ctx.activeUserId` 语义 | 登录 **User.id**（`session.user.id`） | `request-context.ts:372` |
| `Customer.user` 关系 | `@OneToOne(User) user`，`Customer.id` 才是实体主键 | `customer.entity.ts:53` |
| core 解析 Customer | `customerService.findOneByUserId(ctx, user.id)` 可用 | `customer.service.ts:141` |

| 现有能力 | `addBalance`/`deductBalance`/`getBalance`/`applyBalanceChange`、`CustomerBalance`/`BalanceTransaction` 实体、`balance-pay` handler、`redeemCard` 卡密兑充 | recharge-card 各源文件 |

## 2. 范围与边界

- **只扩展 `recharge-card-plugin`**，复用其 `CustomerBalance`/`BalanceTransaction`/`RechargeCardService`。
- **不接真实支付网关**（支付宝/微信）：本次在线充值仅建单（pending），支付接口预留；网关在有真实凭据后由回调驱动 `paid→addBalance` 入账。
- 不新建重复实体/服务。

## 3. 数据模型

### 3.1 新增实体 `RechargeOrder`（充值单）
| 字段 | 类型 | 说明 |
|---|---|---|
| `customer`(ManyToOne)/`customerId` | int | 顾客（**customer.id 口径**） |
| `amount` | int | 充值金额（分） |
| `status` | varchar | `pending`/`paid`/`cancelled` |
| `paymentMethod` | varchar 可空 | 预留网关标识（如 alipay/wechat）；现无网关时留空 |
| `paidAt` | datetime 可空 | 入账/支付时间 |
| `remark` | text 可空 | 备注 |
| `channelId` | int | 渠道隔离（对齐阶段17 铁律） |
| `channels`(ManyToMany) | — | 满足 ChannelAware |

`status`/`paymentMethod` 用显式 `@Column('varchar')` 防 Object 反射（阶段12/27 铁律）。

### 3.2 复用实体
`CustomerBalance`、`BalanceTransaction`（不新增余额实体）。

## 4. 服务能力（扩展 `RechargeCardService`）

### 4.1 口径统一（前置修复）
新私有 `resolveCustomerId(ctx, customerId?)`：给定 `customerId` 直接回退；否则 `customerService.findOneByUserId(ctx, ctx.activeUserId)` → `customer.id`。**所有**余额入口（getBalance/redeemCard/消费/退款/admin 调整/充值单入账）后端先转到 `customer.id` 再读写 `CustomerBalance`/`BalanceTransaction`。修正 balance-payment-handler 的 `createPayment`（用 customer.id）与 `createRefund`（存量已对，保持 customer.id，剔除与消费不一致）。

### 4.2 admin 手工调整
`adminAdjustBalance(input: { customerId, amount, type, remark })`：
- 原子增减：`amount` 为正加、为负减（冲正）；写 `BalanceTransaction(ADJUST/RECHARGE/CONSUME)` 带 remark；返回新余额。
- 幂等：依赖 single 原子 UPDATE + unique(customer,channel)，重复调用可带幂等标识由调用方控制。

### 4.3 shop 充值单（预留网关）
- `createRechargeOrder(amount)` → `status=pending`，返回充值单。
- `payRechargeOrder(id)`：本人+渠道校验 → `status=paid + paidAt` → `addBalance(..., RECHARGE)` 入账；预留 notify 钩子（网关接入后由回调调用同一入账方法，保证幂等——按 RechargeOrder id 判重）。

### 4.4 统一资金流水
- `myBalanceTransactions(options)`：本顾客（customer.id 口径）分页查 `BalanceTransaction`，含类型/金额/余额前后/时间。
- `customerBalances()`（admin）/ `customerBalanceTransactions(customerId)`（admin）。

## 5. 支付/退款增强（balance-pay）

- **防重复扣减**：`createPayment` 先查该 order 是否已有 `Authorized/Settled` 的 balance-pay 支付记录 → 有则 `Declined('Order already paid by balance')`。
- **退款不超该单消费**：`createRefund` 校验 `amount ≤ 该 order 累计 CONSUME 金额`，超则 `Failed`；用 customer.id 落库退回，流水 type=REFUND。
- **余额不足拦截**：沿用 `applyBalanceChange` 原子 `balance >= amt` 守卫（已实现），文案「Insufficient balance」。

## 7. e2e 场景（规划）

1. 插件加载 + 初始余额 0。
2. 卡密兑充回归：redeemCard 入账（现有路径，口径修正后仍通过）。
3. createRechargeOrder 建单 pending；payRechargeOrder 入账 + 幂等（重复 pay 拒）。
4. myBalanceTransactions 流水顺序/类型/余额前后。
5. admin 手工调整加/扣/冲正。
6. 余额支付下单：balance-pay 扣减 + 订单 Settled；不足抛错。
7. 防重复扣减：同单二次 balance-pay 拒。
8. 退款：退 ≤ 消费额入账 REFUND；超退拒。
9. 越权隔离：A 看不到 B 余额/流水；admin 调整需权限。
10. 渠道隔离：B 渠道查不到 A 渠道余额。

## 8. 风险与注意

- **customerId 口径是硬前提**：不改则余额对账不可靠（分裂/贷不到）。实现先修 handler 两处（createPayment 用 customer.id）。
- 改实体建新列/新表后删 `e2e/__data__/*.sqlite` 重跑（sqljs 缓存库铁律）。
- `RechargeOrder`/`BalanceTransaction` 返回类型在 admin/shop 各声明一份，防 `Unknown type`（阶段27 实证）。
- 金额统一「分」bigint/int，跨库安全（对齐阶段24-27）。

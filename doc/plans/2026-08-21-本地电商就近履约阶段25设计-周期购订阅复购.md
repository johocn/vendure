# 阶段25 · 设计（周期购 / 订阅复购：套餐档 + 期次 + 预存款）

依据：本地电商已具备订单（Vendure core）、履约/每包独立发货（阶段8-10）、退款售后（after-sales-plugin 阶段11）、店铺与店主账权（shop-plugin 阶段17/18）、收货地址与配送范围（address-plugin 阶段21/22）、消息触达（notification-plugin 阶段23）、商家财务对账结算（settlement-plugin 阶段24）。周期购的每期履约走"正式订单全链路"，需复用阶段24按单结算与阶段5 `OrderPackage` 履约，自然衔接。

核心：新建 `@vendure/subscription-plugin`，做**买家侧周期购订阅**。买家按套餐档一次性买断 N 期（费用入"周期购预存款"），系统按多频次排期在每个期次日生成正式订单并对预存款按该期价格抵扣，订单进入正常履约与结算全链路；卖家可为每个期次逐期指定商品内容（可从模板改）；最后一期履约完成后发续订提醒，买家手动确认开启新一段。**混合模式 = N 期买断 + 到期可选续订**。

## 1. 目标与非目标

**目标**
- `SubscriptionPlan`（套餐档）：绑定店铺，可配频次（每日 / 每周某天 / 每隔 N 天）、期数 N、每期价格、组合模板（variant×默认数量）。
- `Subscription`（买家实例）：一次买断收全部 N 期总价入预存款；按排期到期自动生成正式订单并对预存款抵扣。
- `SubscriptionOccurrence`（期次）：第 1..N 期逐期状态流转；卖家在履约前为每个期次指定商品内容（可从模板改）。
- 每期生成正式 Order → 进入正常履约（每包发货）+ 阶段24按单结算（按期计入商家应收）。
- 到期续订：最后一期履约后发提醒（复用阶段23），买家手动确认开启新一段。
- 权限隔离：买家（C端）管理自己的订阅；店主管理本店套餐档与期次内容；平台查全部。

**非目标**
- 不做真实代扣/周期性自动扣款（续订靠买家手动确认，无代扣网关）。
- 不做期次内容按季强约束（卖家逐期自由指定，系统仅按期生成，不强校验库存）。
- 不做取消后的退款自动入账（已生成订单的退款走阶段11售后）。
- 不做"预存款"公开支付流水、发票、税务。

## 2. 总体架构

```
买家买断下单（套餐档 N 期）
   → 创建 Subscription（prepaidBalance = 全部 N 期总价）+ 生成 1..N 个 pending 期次
   → 订阅状态 active，接入每日调度

每日调度（job-queue 定时）
   → 扫描排期到期且 pending 的期次，按期次状态机逐个处理
       卖家该期已指定内容 → 按该期价格对预存款抵扣，生成正式 Order
                           （订单标记"已支付"，费用=该期价格）
                           → 进入正常履约（每包发货）+ 阶段24按单结算
       卖家未指定/库存不足 → 期次 skipped（记原因、通知卖家），不阻塞其他期次
       幂等：unique（subscriptionId, periodNo）+ 期次状态机双防重

最后一期履约后 → renewalPending → 发续订提醒（阶段23）
   → 买家手动确认 → 再收全款 → 新建新一段 Subscription；原订阅 expired
```

## 3. 数据模型（`packages/subscription-plugin/src/`）

> 金额一律「分」整数（对齐订单 `WithTax` 口径）；字段/日期写法令照各阶段铁律（`?: Date`、状态 varchar、enum 用 simple-json 避免跨库枚举风险）。

### 3.1 SubscriptionPlan（套餐档）
- 继承 core 基类：`id`/`createdAt`/`updatedAt`。
- `channelId`：`int` 普通列 NOT NULL（阶段17/19 ChannelAware 铁律）。
- `shopId`：`int NOT NULL`，归属店铺。
- `frequency`：`simple-json NOT NULL`，`{ kind: 'daily' } | { kind: 'weekly', dayOfWeek } | { kind: 'everyNDays', interval }`。
- `periods`：`int NOT NULL`，期数 N。
- `periodPrice`：`int NOT NULL`，每期价格（分）。
- `templateItems`：`simple-json nullable`，组合模板 `[{ variantId, quantity }]`，供卖家逐期快速预设。
- `enabled`：`bool NOT NULL default true`。
- `title`/`description`：`varchar nullable`。

### 3.2 Subscription（买家实例）
- 继承 core 基类。
- `channelId`：`int` 普通列 NOT NULL。
- `code`：`varchar NOT NULL`，可读编号。
- `planId`：`int NOT NULL`；`shopId`：`int NOT NULL`；`customerId`：`int NOT NULL`。
- `scheduleJson`：`simple-json NOT NULL`，排期日期列表（每个日期一个期次）。
- `startDate`/`endDate`：`Date nullable`。
- `prepaidBalance`：`int NOT NULL 默认0`，预存款余额（分）。
- `purchasedTotal`：`int NOT NULL`，买断总收款（分）。
- `payOrderId`：`int nullable`，买断主订单。
- `status`：`varchar NOT NULL default 'draft'`，状态机 `draft → active → renewalPending → expired` | `active → cancelled`。

### 3.3 SubscriptionOccurrence（期次）
- 继承 core 基类。
- `channelId`：`int` 普通列 NOT NULL。
- `subscriptionId`：`int NOT NULL`。
- `periodNo`：`int NOT NULL`，第 1..N 期。
- `scheduledDate`：`Date`。
- `sellerItemsJson`：`simple-json nullable`，卖家逐期指定内容 `[{ variantId, quantity }]`（可从模板改）。
- `generatedOrderId`：`int nullable`；`orderCode`：`varchar nullable`。
- `status`：`varchar NOT NULL default 'pending'`，状态机 `pending → orderCreated | skipped | cancelled`。
- 索引：`@Index(['subscriptionId','periodNo'], { unique: true })` 幂等防重。

## 4. 编排（SubscriptionService）

### 4.1 买断开通
- 买家选套餐档 → 用 `OrderService` 生成买断主订单（金额 = `periods × periodPrice`）→ 支付成功事件。
- 支付成功：创建 `Subscription`（`prepaidBalance = purchasedTotal`），按 plan 频次 + startDate 展开 `scheduleJson` 生成 1..N 个 pending `SubscriptionOccurrence`，状态 `active`，接入每日调度。

### 4.2 每日调度（生单抵扣）
- job-queue 每日扫描 active 订阅中 `scheduledDate` 到期且 `pending` 的期次。
- **每期生单**：该期 `sellerItemsJson` 已由卖家指定 → 用 `OrderService` 生成正式 Order（lines = 该期清单；金额 = `periodPrice`）→ 订单以内部支付标记"已支付"（进入阶段24结算口径）→ 期次 `orderCreated`、`prepaidBalance -= periodPrice`。
- **不可履约**：卖家未指定或库存不足 → 期次 `skipped`（记原因、通知卖家），不阻塞其他期次。
- **幂等**：`unique(subscriptionId,periodNo)` + 期次状态机双防重；同一期次即使调度重复命中也不二次生单。

### 4.3 续订
- 最后一期（`periodNo = N`）履约后 → 订阅 `renewalPending` → 发续订提醒（阶段23消息触达）。
- 买家手动确认 → 再次收全部 N 期总价 → 新建新一段 `Subscription`；原订阅 `expired`。
- 买家不确认 → 订阅维持 `renewalPending` 至 `endDate` 后 `expired`。

### 4.4 取消
- 未开始（pending 且未到 scheduledDate）的期次可取消；订阅 `cancelled` 时取消所有 pending 期次。
- 已 `orderCreated` 的期次不走取消，退款走阶段11售后，预存款余额据实退回（仅台账记录，不接退款网关）。

## 5. 权限与归属

- **买家域（C端）**：`@Allow(Permission.Owner)` 自动限定 `customerId = 当前买家`；查我的订阅/期次、手动触发续订确认。
- **店主域（admin，shop-plugin 阶段18）**：`@Allow(manageOwnShop.Permission)` + `requireMyShop`（阶段24 直接仓储实现，避免 DI 环）；管理本店套餐档、为各期次逐期指定商品内容。
- **平台管理端**：`@Allow(Permission.UpdateSettings)`；查看全部套餐档/订阅/期次，停用套餐档。
- 跨插件访问 Order/Shop 用 `OrderService` + 直接仓储（`getRepository(ctx, Shop)`），避免注入 shop.service 的 DI 环（阶段19 铁律）。

## 6. GraphQL 接口

**shop-api · 买家侧**
- `availablePlans(shopId?, options): SubscriptionPlanList!`：可购套餐档。
- `mySubscriptions(options): SubscriptionList!`：我的订阅（含剩余期次、预存款余额）。
- `mySubscription(id): Subscription` / `mySubscriptionOccurrences(subscriptionId, options)`：我的订阅与期次。
- `createSubscription(planId, input { startDate }): ...`：买断开通（返买断主订单待支付）。
- `confirmRenewal(id): Subscription`：续订确认（开启新一段）。

**admin-api · 店铺店主侧（`@Allow(manageOwnShop.Permission)`）**
- `createSubscriptionPlan(input)` / `updateSubscriptionPlan(id, input)`：本店套餐档 CRUD。
- `myShopSubscriptionPlans(options)`：本店套餐档列表。
- `mySubscriptionsByShop(options)`：本店关联的买家订阅。
- `myShopSubscriptionOccurrences(subscriptionId, options)`：本店订阅期次。
- `setSubscriptionOccurrenceItems(id, items): SubscriptionOccurrence`：为该期次指定商品内容（含库存校验提示）。

**admin-api · 平台管理端（`@Allow(Permission.UpdateSettings)`）**
- `subscriptionPlans(options)` / `subscriptions(options)` / `subscriptionOccurrences(options)`：全部套餐档/订阅/期次。
- `setSubscriptionPlanEnabled(id, enabled)`：停用/启用套餐档。

## 7. 错误处理

- 预定频次排期展开失败 / startDate 非法 → `UserInputError`。
- 每期抵扣时预存款不足（并发/异常）→ 期次保持 `pending`、订阅告警、通知平台与买家，不做部分抵扣。
- 卖家未指定内容或库存不足 → 期次 `skipped`（记录原因），不阻塞其他期次。
- 非法状态迁移（如 `expired` 后再续订、`cancelled` 后 schedule）→ `UserInputError`。
- 买家访问他人订阅 / 店主访问非本店订阅 → `Forbidden`（归属校验）。
- 重复生单 → 唯一约束 + 状态机抛错防重。

## 8. 测试（e2e，≥13）

复用 settlement-plugin e2e 骨架（`InventoryPlugin.init()` + `ShopPlugin.init({})` + `SubscriptionPlugin.init({})` + `SettlementPlugin.init({})`）。覆盖：
1. 插件加载 + 创建套餐档（每日/每周/每隔N天三种频次）
2. 买断开通：一次收全款、生成 N 个期次、预存款 = 总价
3. 每日调度：到期期次生成正式订单 + 预存款按该期价抵扣 + 订单进入正常履约
4. 多频次排期展开正确（每周某天 / 每隔 N 天）
5. 卖家逐期指定内容：该期订单 lines = 卖家清单
6. 未指定内容/库存不足 → 期次 skipped，不阻塞其他期次
7. 幂等：同一期次不重复生二单（unique(subscriptionId,periodNo)）
8. 与阶段24结算联动：每期订单按单计入商家应收
9. 最后一期履约 → renewalPending → 发续订提醒
10. 买家确认续订 → 新一段订阅 + 再收全款；原订阅 expired
11. 取消：未开始期次可取消，订阅 cancelled
12. 越权隔离：买家看不到他店订阅、店主看不到非本店期次
13. 平台停用套餐档 / 查全部订阅

## 9. 风险与前置依赖

- 依赖阶段24 settlement-plugin 按单结算（每期订单计入商家应收）；e2e 把 `SettlementPlugin.init({})` 一并装配验证联动。
- 依赖阶段23 notification-plugin 发续订提醒（发消息能力，站内信）。
- 依赖 `OrderService` 生成正式订单 + 内部支付标记"已支付"以进入结算口径；需对齐本项目支付实现（debug-payment / singleStageRefundablePaymentMethod）。
- 依赖 shop-plugin 店主账权 `requireMyShop` + `manageOwnShop`。
- 金额单位为「分」，预存款充值/抵扣/续订收全款统一整数，跨库安全。
- 真实代扣网关不在范围：续订一律手动确认，避免支付边界风险。

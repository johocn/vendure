# 阶段48 实施计划：店主商品管理

> 目标：补齐店主自营后台的「商品域」能力 —— 上下架（enabled 切换）、编辑基础信息、库存聚合查看。
> 归属：复用 shop-plugin `manageOwnShop` 权限 + service 层 `requireMyShop / getMyShopProductOrThrow` 二次校验。

## 背景与现状（阶段47 沉淀）
- 店主账权体系已落地：`requireMyShop`（activeUserId→Administrator→Shop.administratorId+status=active）、
  归属隔离（`Product.customFields.shopId === shop.id`）。
- 已有能力：
  - 商品增删到店：`addProductToMyShop / removeProductFromMyShop`
  - 基础信息编辑：`updateMyShopProduct`（name/description）
  - 库存明细：`myShopStock`（逐仓逐变体水位）、`myShopStockAdjust`（绝对值校准）【阶段47】
- 缺口：
  - 无「上下架」：无法切换本人商品 `Product.enabled`（及变体 enabled）。
  - 无「库存聚合查看」：商品列表只有逐变体明细，缺商品级汇总（变体数/合计库存/可售）。

## 交付范围（A~B）

### A. 上下架（shop-plugin）
- `ShopService.setMyShopProductEnabled(ctx, productId, enabled): boolean`
  - `requireMyShop` → `getMyShopProductOrThrow`（归属校验）
  - 写 `Product.enabled`，并同步全部 `ProductVariant.enabled`
- `MerchantResolver.setMyShopProductEnabled`  mutation，`@Allow(manageOwnShop.Permission)`
- admin schema：`type Mutation { setMyShopProductEnabled(productId: ID!, enabled: Boolean!): Boolean! }`

### B. 库存聚合查看（inventory-plugin）
- `InventoryService.myShopProductStock(ctx, productId): { productId, variantCount, totalOnHand, totalAvailable }`
  - 复用 `requireMyShop` / `assertMyProduct`
  - 全部变体 × 全部分页仓，合计 `stockOnHand` 与 `stockOnHand - stockAllocated`
- `InventoryMerchantResolver.myShopProductStock` query，`@Allow(manageOwnShop.Permission)`
- admin schema：`type MerchantProductStock { productId variantCount totalOnHand totalAvailable }`

> 说明：编辑基础信息（name/description）已在阶段18 `updateMyShopProduct` 提供，本阶段不复刻。

## 构建与部署（铁律）
本地构建 fa-shop-plugin `lib/` + inventory-plugin `dist/`，提交入库；服务器仅 `git pull + pm2 restart`。

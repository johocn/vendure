# 阶段30 设计：会员等级权益体系

> 日期：2026-08-21
> 项目：Vendure 本地化电商（d:\zhao\vendure）
> 前置：阶段15（会员积分抵现闭环）已完成：积分（赚/花/取消回退/退款回退/过期）+ 成长值 + **硬编码 5 档等级**（Channel customFields `/levelNThreshold/levelNName` + Customer `memberLevel` int），且阶段15明确把「等级权益差异化」（金卡多抵等）列为**非目标**。
> 本文档为设计稿，实施见 companion 文件：`2026-08-21-本地电商就近履约阶段30实施计划-会员等级权益体系.md`

## 1. 背景与目标

阶段15 打通了「赚积分 → 花积分抵现 → 回退 → 过期」的会员经济链路，但**等级只有档位没有权益**：不同等级的顾客享受完全相同的待遇（同积分获取倍率、同抵现折算、无免运费、无专属折扣），会员等级形同虚设、缺乏成长价值。

本阶段目标：**把等级从"标签"升级为"权益体系"**，让更高等级获得可感知的差异化待遇，从而激励顾客持续消费提升成长值，形成「消费 → 成长值 → 升级 → 权益 → 更愿意消费」的运营闭环。

## 2. 范围

### 2.1 目标（In Scope）

以**新建 `MemberTier` 实体表驱动**承载等级定义与每档权益（取代硬编码 5 档），落地四项权益：

1. **等级 = MemberTier 表**：`tierLevel` + `threshold`(成长值门槛) + `name`；admin 可动态增删改档位，首启由既有 channel 5 档字段播种（向后兼容）
2. **积分获取倍率 `pointsMultiplier`**：Delivered 给积分时 × 当前等级倍率（金卡 1.5 → 赚分更快）
3. **抵现增强 `redeemDiscountRate`**（千分比）+ `redeemCapRatio`（可抵占订单比例上限）：高等级同分抵更多、可抵更高比例
4. **免运费 `freeShippingThresholdLevel`（channel 级）**：达指定等级 → 结算运费报价 0（新增「等级免运费」运费方法）
5. **等级专属折扣 `specialDiscountRate`**（千分比）：Promotion 条件按 `customer.memberLevel` 匹配 → 订单折扣动作

### 2.2 非目标（Out of Scope）

- 多等级叠加/跨渠道联动（等级权益按 channel 隔离，一眼权）
- 积分兑换实物 / 积分 + 优惠券叠加细则（沿用阶段15「各 Promotion 独立生效」约定）
- 会员等级降级（复用现有只升不降语义）
- 生日礼/专属客服/优先派送等线下权益（仅实现上述 4 项可结算验证的数字权益）

## 3. 领域模型

### 3.1 MemberTier 实体（新增，ChannelAware）

| 字段 | 类型 | 说明 |
|------|------|------|
| `tierLevel` | int | 档位序号（1 = 最低） |
| `threshold` | int | 成长值门槛（达到即达该档） |
| `name` | varchar | 等级名（普通会员/银卡/…） |
| `pointsMultiplier` | int | 积分获取倍率（千分比，150 = 1.5 倍） |
| `redeemDiscountRate` | int | 抵现折扣率（千分比，默认 1000 = 1 分抵 1 分） |
| `redeemCapRatio` | int | 可抵占订单金额上限比例（千分比，默认 500 = 最多抵 50%） |
| `specialDiscountRate` | int | 等级专属折扣率（千分比，0 = 无专属折扣） |
| `channelId` | int | ChannelAware 普通列 NOT NULL |
| `channels` | ManyToMany | 满足 ChannelAware |

约束：`@Index(['tierLevel','channelId'], { unique: true })` —— 每渠道每档唯一。

### 3.2 Channel 自定义字段（新增 1 个）

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `freeShippingLevel` | int | 0 | 启用等级免运费所需最低 tierLevel（0 = 不启用免运费） |

> 现有 `level1Threshold…level5Threshold/Name` + `pointsEarnRatio/pointsEarnOnShipping` **保留**：作为首启播种与费率兜底来源。

### 3.3 订单自定义字段 / Customer 字段

- Customer `memberLevel`（int）**保留**为等级快照（等级判定改查表后，升级时回写该快照）。
- 免运费如需在订单上留痕，可加 `Order.freeShippingApplied`（bool，public）可选——见实现计划决定，非必须。

## 4. 核心机制

### 4.1 等级表驱动（取代硬编码）

- `getTierByGrowthValue(ctx, growthValue)`：`getRepository(ctx, MemberTier)` 按 `channelId` 查全部档，取 `threshold <= growthValue` 的最大 `tierLevel`；无则默认 1。
- `calculateLevel(ctx, growthValue)` 改调 `getTierByGrowthValue`（原基于 channel 字段的逻辑废弃/兜底）。
- `buildMemberInfo` 读表返回 `tierLevel/tierName/nextTierThreshold/nextTierName` + 权益（积分倍率/抵现率/专属折扣率）。
- **播种**：插件 bootstrap 时若本渠道无 MemberTier 记录，从 channel `levelNThreshold/levelNName` + 默认权益（×1 倍率 / 抵现率 1000 / 封顶 50% / 无专属折扣）逐档插入——一次、幂等（查存在即跳过）。

### 4.2 积分获取倍率（Delivered）

`handleOrderDelivered` 现在 `points = floor(base × ratio)`（ratio=pointsEarnRatio）。改为：
```
tier = getTierByGrowthValue(ctx, customer.growthValue)
ratio = tier.pointsMultiplier  // 这里 pointsMultiplier 即"每元积分"的整体倍率，覆盖/增强原 ratio
points = floor(base × ratio)
```
> 决策：为免双重作用域混乱，**CPU 路径以 `tier.pointsMultiplier` 为准**（取代 channel `pointsEarnRatio` 作为积分货币倍率）；原 `pointsEarnRatio` 保留仅作播种默认。成长值 `addGrowthValue(floor(base))` 逻辑不变。

### 4.3 抵现增强（redeemPoints）

现有折算 `discountAmount = floor(points / pointsPerYuan) × 100`，且要求 `< subTotal`。改为按等级增强：
```
tier = getTierByGrowthValue(...)
rate = tier.redeemDiscountRate（默认 1000 = 原折算）
effectivePerYuan = ceil(pointsPerYuan × 1000 / rate)   // 率越高，每分抵得越多
discountAmount = floor(points / effectivePerYuan) × 100
cap = floor(subTotal × tier.redeemCapRatio / 1000)
discountAmount = min(discountAmount, cap)
// 拦截：<=0 或 (无封顶时为 0) 或 discountAmount >= subTotal（仍不允许全免）
```
`pointsPerYuan` 读取沿用 channel 配置（默认 100）。

### 4.4 等级免运费（运费环节）

- 新增 ShippingEligibilityChecker `memberTier-free-shipping-eligibility`（条件：订单 customer 等级 >= `channel.freeShippingLevel`）。
- 新增 ShippingCalculator `memberTier-free-shipping`（报价 0 元：`{ price: 0, priceWithTax: 0, metadata }`）。
- 管理员 channel 配置 `freeShippingLevel` 后，为该渠道配置挂这组运费方法即启用。
- ⚠️ 复用阶段22 经验：**勿用 `shouldRunCheck` 做缓存守卫**（会缓存跳过 check），把「未启用/等级不足 → 不达标」判据写进 check；EligibilityChecker 若返回 false 该方法不出现，Calculator 不执行。等级随渠道配置/顾客成长值外部变化，**不要依赖 shouldRunCheck 缓存**。

### 4.5 等级专属折扣（Promotion）

- 新增 PromotionCondition `tier_eligible`：读 `order.customer.customFields.memberLevel`，若 `>=` 该条件配置的 `minLevel` 返回 `{ memberLevel }`。
- 新增 PromotionOrderAction `tier_discount`：读 `tier.specialDiscountRate`（按订单 customer 当前等级查表）→ 返回 `-floor(subTotalWithTax × rate / 1000)`（clamp 到 subTotalWithTax）。
- admin 建一张「等级专属折扣」促销 = `tier_eligible` 条件 + `tier_discount` 动作即可生效（与阶段13-15 促销动态折扣同机制）。

## 5. 状态机/事件接线

| 事件/时机 | 动作 |
|------|------|
| `OrderStateTransitionEvent → Delivered` | 按 `tier.pointsMultiplier` 加积分 + 成长值（升级回写 memberLevel 快照） |
| `OrderStateTransitionEvent → Cancelled` / `Refund → Settled` | 沿阶段15 回退逻辑，不变 |
| admin `updateTier(s)` / `setTiers()` | 写 MemberTier；可选触发等级重算（本期：不改存量等级，仅后续判定生效） |
| bootstrap | 播种默认 MemberTier（幂等） |

## 6. 权限

- admin（`Permission.UpdateSettings`）：`memberTiers` 查询、`saveTiers(input)`（整体保存各档 → 幂等 upsert）、channel `freeShippingLevel` 配置。
- shop（`@Allow(Authenticated)`）：`myMemberInfo` 扩展返回权益字段（tier/nextTier/pointsMultiplier/redeemDiscountRate/redeemCapRatio/specialDiscountRate/freeShippingLevel）；`myTier()`（当前等级权益详情）。
- 免运费/专属折扣在结算期由 Promotion/shipping 自动生效，无独立 user mutation。

## 7. 与已建体系衔接

- 积分/回退：阶段15 原链路不动。
- 免运费：阶段22 配送 checker/calculator 机制（注意 shouldRunCheck 缓存坑）。
- 专属折扣：阶段12/13-15 促销动态折扣机制（PromotionCondition/Action）。
- 等级快照 `Customer.memberLevel`：阶段15 已有；升级时回写。

## 8. 测试（独立 e2e）

- 首启播种：无 MemberTier 时 bootstrap 生成默认 5 档（1-5 threshold/name 对齐 channel 字段），幂等。
- 等级判定：手动设成长值 → `myMemberInfo`/`myTier` 返回对应档位 + 下一档门槛 + 权益。
- 积分倍率：金卡(×1.5) 送达加积分 = floor(base×1.5)，成长值 = floor(base)。
- 抵现增强：高等级同分抵更多 + 封顶比例生效；低等级受 cap 限制。
- 免运费：配 `freeShippingLevel` + 挂运费方法 → 达标等级订单结算运费 0；不达标仍收基础运费；shopClient 结算报价断言。
- 专属折扣：建促销 → 高等级订单结算含专属折扣；低等级无折扣。
- 渠道隔离：新渠道无 MemberTier（空），播种后各自独立。
- 权限/越权：shop 非本人不可改；admin 保存整体档位幂等。

运行：插件目录内 `$env:PACKAGE='member-level-plugin'; npx vitest run --config vitest.config.mts e2e/member-tier.e2e-spec.ts`；改实体后删 `e2e/__data__/*.sqlite`。

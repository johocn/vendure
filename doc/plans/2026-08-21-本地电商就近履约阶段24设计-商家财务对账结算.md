# 阶段24 · 设计（商家财务对账结算：账务台账 + 提现）

依据：本地电商已具备订单（Vendure core）、退款/售后（after-sales-plugin）、店铺与店主账权（shop-plugin 阶段17/18）、收货地址与配送范围（address-plugin 阶段21/22）、促销积分（coupon/group-buy/flash-sale/member-level）、消息触达（notification-plugin 阶段23）。按店金额归集已有现成工具 `resolveOrderShopMap`/`computeShopFees`（address-plugin），对账口径参考 marketplace-plugin `SettlementService`。

核心：新建 `@vendure/settlement-plugin`，做**平台 ↔ 商家的账务台账**。支付在平台侧收，本阶段把订单货款+运费按店铺归属归集到商家账户，扣除平台佣金，形成应收明细/账户余额；商家可发起**提现申请**，平台**审核打款**入账。不接真实分账网关，纯账务台账 + 提现流转。

## 1. 目标与非目标

**目标**
- 商家自有资金账户（一店一账户），可查`可提现余额`与累计快照。
- 订单达 completed 口径（Shipped / Delivered / Completed）事件驱动，自动按店产生结算明细并计入账户余额（商品货款 + 运费 − 平台佣金）。
- 每店平台佣金率可配置（平台管理端）。
- 商家（店主，复用阶段18账权体系）可查账户余额、结算明细流水，并发起提现申请。
- 平台管理端审核提现（同意打款 / 驳回），记录打款信息。

**非目标**
- 不接真实分账网关（微信/支付宝分账、T+1 自动打款等）。
- 不做自动批量打款到账（仅台账记录平台已打款）。
- 不处理佣金的费用明细拆分、发票、税务申报。
- 不做发货前预付款/垫资。

## 2. 总体架构

```
订单完成履结（Shipped/Delivered/Completed）
   OrderStateTransitionEvent → SettlementService.handleOrderSettled(order)
        │  用 resolveOrderShopMap/computeShopFees 按店归集货款+运费
        │  扣平台佣金（每店佣金率，可配置）
        │  幂等（orderId×shopId 判重）写入 结算明细 SettlementEntry
        ▼
   MerchantAccount（商家资金账户）余额与累计快照实时更新
        │
  店主域（阶段18账权）
   ├─ 查账户余额/结算流水/历史汇总
   └─ 发起提现 WithdrawalRequest(pending)
        │
  平台管理端
   ├─ 审核提现 approve → paid（记录打款） / reject
   └─ 配置每店佣金率
```

## 3. 数据模型（`packages/settlement-plugin/src/`）

### 3.1 MerchantAccount（商家资金账户）
- 继承 core 基类：`id`/`createdAt`/`updatedAt`。
- `channelId`：`int` 普通列 NOT NULL（对齐阶段17/19 ChannelAware 铁律）。
- `shopId`：`int NOT NULL`，一店一账户。
- `commissionRate`：`float NOT NULL 默认0`，平台佣金率（%）。
- `availableBalance`：`int NOT NULL 默认0`，可提现余额（分）。
- `totalGoodsAmount`：`int NOT NULL 默认0`，累计商品货款（分）。
- `totalShippingAmount`：`int NOT NULL 默认0`，累计分摊运费（分）。
- `totalCommission`：`int NOT NULL 默认0`，累计平台佣金（分）。
- `totalWithdrawn`：`int NOT NULL 默认0`，累计已提现（分）。
- 索引：`@Index(['channelId','shopId'], { unique: true })` 保证一店一账户。

> 金额一律「分」整数（对齐订单金额 `WithTax` 口径），避免浮点误差。

### 3.2 SettlementEntry（结算明细）
- 继承 core 基类。
- `channelId`：`int` 普通列 NOT NULL。
- `shopId`：`int NOT NULL`。
- `orderId`：`int NOT NULL`；`orderCode`：`varchar NOT NULL`。
- `goodsAmountWithTax`：`int NOT NULL`，该店商品货款含税（分）。
- `shippingAmountWithTax`：`int NOT NULL`，该店分摊运费含税（分）。
- `commissionAmount`：`int NOT NULL`，该店平台佣金（分）。
- `netAmountWithTax`：`int NOT NULL`，商家应收 = goods + shipping − commission（分）。
- `settledAt`：`Date`（可选 Date 列，勿写死 type，阶段11 铁律）。
- 索引：`@Index(['orderId','shopId'], { unique: true })` 幂等防重（事件重复只入一次）。

### 3.3 WithdrawalRequest（提现申请）
- 继承 core 基类。
- `channelId`：`int` 普通列 NOT NULL。
- `shopId`：`int NOT NULL`。
- `amount`：`int NOT NULL`，申请提现金额（分）。
- `status`：`varchar NOT NULL default 'pending'`，状态机 `pending → approved → paid` | `pending → rejected`。
- `reviewNote`：`varchar nullable`，平台备注。
- `paidAt`/`settledAt`：`Date nullable`。

## 4. 触发编排（SettlementService）

### 4.1 订单完成入账
- `onApplicationBootstrap` 订阅 `OrderStateTransitionEvent`。
- 事件 order 关系不完整（阶段4/5/15 铁律）：用 `orderService.findOne(id, [relations])` 重载（含 lines/productVariant，用于按店归集）。
- 仅在 `toState ∈ { Shipped, Delivered, Completed }` 触发；`Completed` 是我们的自定义终态（阶段10，需确认 core 状态名；若本项目用 `Delivered`/`Completed` 映射，按实际状态机确定集合）。
- 按店归集：`computeShopFees`（address-plugin）拿到每店 subtotal + shipping fee；商品货款 = 该店 line `linePriceWithTax` 合计，运费 = 该店 `fee`。
- 扣佣金：`commissionAmount = round(净应收 × commissionRate/100)`；`netAmountWithTax = goods + shipping − commission`。
- 幂等：SettlementEntry 按 `orderId×shopId` unique 判重。
  - **账户余额/累计快照只在「新建明细」成立时累加一次**——即查询 SettlementEntry 落入 `INSERT` 分支，随后同步累加账户；若明细已存在（`skip`），不累加。这样同一订单经 Shipped→Delivered→Completed 多次事件也只入账一次，多店订单每店分别入账一次。
- 账户累加（仅在新建明细后执行）：
  `availableBalance += netAmountWithTax`；`totalGoodsAmount += goods`；`totalShippingAmount += shipping`；`totalCommission += commission`。

### 4.2 提现流转
- 店主发起：`amount ≤ availableBalance` 才允许；创建 `WithdrawalRequest(pending)`，**不发钱不动余额**。
- 平台审核通过 `approve(pending→approved)` → 再 `pay(pending/approved→paid)`：校验余额足够，扣减 `availableBalance -= amount`、`totalWithdrawn += amount`，记 `paidAt`。
- 平台驳回 `reject(pending→rejected)`：不扣余额，记录 `reviewNote`。
- 状态机校验：仅 `pending→approved`、`pending→rejected`、`approved→paid` 合法，非法迁移抛 `UserInputError`。

## 5. 权限与归属

- **店主域**（shop-plugin 阶段18）：`@Allow(manageOwnShop.Permission)` + `requireMyShop`。所有店主查询/操作自动限定 `shopId = 我的店`，无归属或非 active → `Forbidden`。
- **平台管理端**：`@Allow(Permission.UpdateSettings)`。审核提现、配置佣金率、查全部商户账户/明细。
- 跨插件访问 Shop 用直接仓储（`getRepository(ctx, Shop)`），避免注入 shop.service 的 DI 环（阶段19 铁律）。

## 6. GraphQL 接口

**admin-api · 店铺店主侧（`@Allow(manageOwnShop.Permission)`）**
- `myMerchantAccount: MerchantAccount!`：我的账户（余额 + 累计快照 + 佣金率）。
- `mySettlementEntries(options): SettlementEntryList!`：我的结算流水（分页，按 settledAt DESC）。
- `myWithdrawalRequests(options): WithdrawalRequestList!`：我的提现记录。
- `requestWithdrawal(amount: Int!): WithdrawalRequest!`：发起提现（额度校验）。
- `settlementSummary(from,to): SettlementSummary!`：按时间窗汇总（货物/运费/佣金/净额）。

**admin-api · 平台管理端（`@Allow(Permission.UpdateSettings)`）**
- `merchantAccounts(options): MerchantAccountList!`：全部商户账户。
- `settlementEntries(shopId, options): SettlementEntryList!`：某店结算明细。
- `withdrawalRequests(options): WithdrawalRequestList!`：待/已审核提现列表。
- `approveWithdrawal(id): WithdrawalRequest!`：审核通过（→approved）。
- `payWithdrawal(id): WithdrawalRequest!`：打款（→paid，扣余额）。
- `rejectWithdrawal(id, note): WithdrawalRequest!`：驳回（→rejected）。
- `setMerchantCommissionRate(shopId, rate): MerchantAccount!`：配置每店佣金率（幂等 upsert 账户并写率）。

## 7. 错误处理

- 店主发起提现超额 → `UserInputError('Insufficient balance')`。
- 平台打款时余额不足（已提现后并发）→ `UserInputError`，拒绝。
- 非法状态迁移 → `UserInputError`。
- 店主无归属/非 active → `Forbidden`（requireMyShop）。
- 商品未归属店铺（shopId 缺失）→ 该行不计入任何账户（skip），不影响其他店。
- 佣金率缺省：商户账户未建时用平台默认 `defaultCommissionRate`（插件 options 可配）。

## 8. 测试（e2e，≥13）

复用 address-plugin e2e 骨架（`ShopPlugin.init({})` + `SettlementPlugin.init({})`）。覆盖：
1. 插件加载 + 初始账户（未营收）返回 0 余额
2. 订单送达（Delivered）→ 按店产生结算明细 + 账户余额正确
3. completed 多种终态（Shipped/Delivered/Completed）均入账
4. 佣金计算正确（rate=10 → commission = 10%净应收）
5. 多店拆账：同一订单含两店商品，各自产生明细
6. 幂等：同一订单事件重复触发不双计（明细唯一 + 余额不重复累加）
7. 运费计入商家应收（shipping 分摊正确）
8. 店主查 myMerchantAccount / mySettlementEntries 越权隔离（A 店看不到 B 店）
9. 店主发起提现（额度内成功）
10. 提现超额拒绝（amount > availableBalance）
11. 平台审核 approve → pay：余额扣减、totalWithdrawn 累加
12. 平台驳回 rejected：余额不变
13. 平台配置佣金率 setMerchantCommissionRate，后续订单按新率入账

## 9. 风险与前置依赖

- 依赖 address-plugin `computeShopFees`/`resolveOrderShopMap`（按店归集），e2e 用 createShop + assignProductsToShop 准备归属。
- 依赖 shop-plugin 店主账权 `requireMyShop` + `manageOwnShop` 权限做归属隔离。
- 订单完成状态名需与本地自定义状态机实际对齐（Completed/Delivered），e2e 以真实状态机为准驱动订单。
- 金额单位为「分」，所有入账/提现/汇总统一整数，跨库安全。

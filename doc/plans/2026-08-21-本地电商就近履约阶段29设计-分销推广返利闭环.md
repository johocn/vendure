# 阶段29 设计：分销 / 推广返利闭环

> 目标：让普通用户成为推广员（分销），通过专属邀请码/链接把新用户拉进平台并终身绑定关系；好友下单送达后，推广员按订单行获推广佣金，支持商品级可配费率与「商家让利 / 平台补贴」可配负载方；佣金以「待提现 → 人工打款」兑付。完整衔接订单/退款/结算/多店店铺体系，一级分销合规。

## 业务闭环

```
用户申请成为推广员(生成唯一code) → 分享专属码/链接
  → 新用户点击或输码首次绑定关系(终身一次)
  → 好友下单支付 → 结算 → 订单送达(→Delivered) 按行生成推广佣金 pending
  → 若退款(Settled) → 该单佣金回滚 reversed
  → 推广员佣金累计"可提现" → 发起提现 AffiliateWithdrawal → 平台店主人工打款置 paid
```

## 技术路线

- 新插件 `@vendure/affiliate-plugin`，沿用既有四件套 + admin/shop 双 API schema + local `tsc` 生成 lib 入库 + e2e。金额统一分（bigint）。

## 核心实体

### Affiliate（推广员）
- `userId`(int)、`homeChannelId`(int)、`shopId`(int nullable，为空=全局推广，绑定该店可授予店主域配置权限)、`code`（varchar `@Index({unique:true})` 推广码）、`status`（varchar `active|suspended`）
- `totalCommission`(bigint 累计)、`withdrawableCommission`(bigint 可提现余额，pending 汇总/已返posable)
- ChannelAware（channelId 普通列 + ManyToMany Channel）

### AffiliateRelation（一级关系绑定）
- `affiliateId`(int)、`customerId`(int)、`channelId`(int)、`bindSource`(varchar `click|code`)、`boundAt`(datetime)
- `@Index({ unique: true }) customerId` —— **一个顾客终身只绑一次**（首绑终身，无有效期）

### AffiliateCommissionEntry（佣金 ledger）
- `affiliateId / customerId / orderId(orderLineId) / shopId / baseAmount(成交额分)`
- `rate`(int 千分比 实际生效费率)、`commissionAmount`(bigint)、`loadOn`(varchar `merchant|platform` 负载方)
- `status`(varchar `pending→paid→reversed`)
- `@Index({ unique: true }) (orderId, orderLineId)` —— 幂等，一订单行一笔佣金

### AffiliateWithdrawal（提现单）
- `affiliateId / amount / status(pending|paid|rejected) / requestedAt / paidAt / note`
- ChannelAware

## 绑定规则

- 推广员分享专属 `code`/链接；新用户点击链接（decode 绑定）或输码绑定。
- **首绑终身**：一个 `customerId` 唯一关系，重复绑（已有关系）拦截；同人自绑（customer === affiliate 的 customer）拦截。
- 绑定在好友首次下单（或注册/首次登录）时落库一次。

## 佣金率优先级（商品级可配）

- `Product.customFields.affiliateRate`（int 千分比，商品级） → 店铺级配置（店铺推广费率） → 全局默认（插件 options `defaultRate`）。
- 取订单行主商品费率：OrderLine 无私货 productId（阶段22/24/28 铁律），须 `line.productVariant.productId → Product`；行 `shopId = Number(product.customFields.shopId)`。
- 每行生成 `AffiliateCommissionEntry`（rate=命中费率、baseAmount=行成交额分、commissionAmount=round(base×rate/1000)、loadOn=配置的负载方）。

## 返佣时机与回滚

- 生成：`OrderStateTransitionEvent` filter `toState==='Delivered'`（阶段10/24/27/28 铁律，勿用 Completed）；事件 `order` 关系需 `orderService.findOne` 重载 lines/productVariant/product/translations + customer。
- 统一幂等：`getOrCreateCommissions(ctx, order)` 按 `(orderId, orderLineId)` 查存在即返。
- 回滚：`RefundStateTransitionEvent` filter `toState==='Settled'` → 该单全部 pending 佣金置 `reversed`，并从可提现余额扣回（幂等）。

## 兑付（待提现 + 人工打款）

- 送达生成佣金并入 `withdrawableCommission`（可提现余额）。
- 推广员 `requestWithdrawal(amount)` 生成 `AffiliateWithdrawal(pending)` 并冻结该笔（余额扣减待打款）。
- 平台/店主 `payWithdrawal(id)` 置 `paid`；`rejectWithdrawal` 置 `rejected` 并回放余额。
- 余额守恒校验：`withdrawableCommission = 累计已返 - 已提现(pending/paid) - 已回滚`。

## 权限

- 平台运营（`Permission.UpdateSettings`）：审启/封禁推广员、配置费率/负载方、打款/驳回提现。
- 店主域（复用阶段18 `requireMyShop`）：查看本店关联推广与佣金（仅本 shopId）。
- C 端（`@Allow(Authenticated)`）：`myAffiliate`（状态/佣金/可提现）、推广码、`myCommissionEntries`、`requestWithdrawal`。

## 与已建体系衔接

- 店铺归属/店主鉴权：阶段17/18 `Product.customFields.shopId` + `requireMyShop`。
- 佣金时机：对齐阶段24 结算、27 团长佣金（Delivered）；退款回滚对齐 11/15。
- 结算负载：`loadOn=merchant` 时佣金并入商家账（商家让利单列）；`platform` 时平台补贴。

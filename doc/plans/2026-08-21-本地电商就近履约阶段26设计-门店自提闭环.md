# 阶段26 · 设计（门店自提闭环：提货码生成 + 一次性核销）

依据：本地电商已有订单（Vendure core）、每包独立发货履约（阶段5 OrderPackage/阶段8-10）、售后（after-sales-plugin 阶段11）、店铺与店主账权（shop-plugin 阶段17/18）、收货地址与按店配送范围（address-plugin 阶段21/22 含 `delivery-plugin` 的自提地基）、消息触达（notification-plugin 阶段23）、商家财务对账结算（settlement-plugin 阶段24）、周期购（subscription-plugin 阶段25）。

`delivery-plugin` 已具备自提**前半程**：`Order.customFields.deliveryType='pickup'`、自提点 `PickupLocation` 单选（`setPickupLocation`/`getPickupLocations`）、店主侧交付确认 `confirmPickupHandover`；前端订单中心已预留 `pickupCode`（提货码）空槽。阶段26 补齐**核销后半程**：固定提货码生成 + 顾客/店员一次性核销，联动订单 Delivered 与阶段24结算。

核心：新建 `@vendure/pickup-plugin`，做**自提单核销闭环**。买家付款后懒生成唯一提货码（幂等一生对一单）；卖家备货完成（Shipped）后才开放核销；顾客凭码自助核销或店员凭码核销，一次核销后推进 Fulfillment→Delivered（订单完成 + 进入商家应收），码即时失效；订单取消则未核销码作废。

## 1. 目标与非目标

**目标**
- 为 pickup 类型已付款订单懒生成固定提货码（唯一、可重复查询、幂等）。
- 备货完成（存在 Shipped Fulfillment）后才开放核销；核销时推进全部 Shipped Fulfillment→Delivered。
- 顾客自核销（`claimMyPickup`）与店员核销（`claimPickupByShop`）共用同一闸门与幂等单次语义。
- 核销后订单达 Delivered → 自动进入阶段24按单结算（商家应收出现该单）。
- 订单取消 → 未核销提货码作废。
- 权限隔离：顾客（Owner 归属）、店主（manageOwnShop + requireMyShop）、平台（UpdateSettings）。

**非目标**
- 不做真实自提柜格口/门禁硬件联动、不做地图选点 SDK（坐标由前端采集，沿用 delivery-plugin 现成自提点）。
- 不做动态一次性码 / 过期轮换码（固定码，未核销一直有效）。
- 不重建自提点管理、不打穿 delivery-plugin 的自提点与配送字段语义（跨插件仓储隔离读）。
- 不做虚拟商品卡密 / 兑换码体系（`nshop` 订单中心 `redeem` slot 属未来另一闭环）。

## 2. 总体架构

```
pickup 订单付款成功
  → 顾客 myPickupCode(orderId)：懒生成 PickupRedemption(纯 code=generated)，幂等返回同一码
  → 卖家备货发货 → 订单存在 Shipped Fulfillment（备货完成，核销闸门开放）

核销（顾客 claimMyPickup(orderId,code) 或 店员 claimPickupByShop(code)）
  校验：订单是 pickup + 存在 Shipped Fulfillment + redemption 存在且 status=generated + 码匹配
  → 置 redeemed（claimedAt/claimedBy/claimChannel）
  → 推进全部 Shipped Fulfillment→Delivered + 写 customFields.pickupClaimed=true
  → 订单 Delivered → 阶段24结算自动计入商家应收（货+运−佣）
  幂等：核销后同码再次使用 → 拒绝（status=redeemed）

订单进入 Cancelled → 其未核销 PickupRedemption 置 void（事件订阅）
```

> 说明：阶段24结算在订单达 Shipped/Delivered 即触发（熵改前已如此），故核销推进 Delivered 时结算已自然联动，无需新增耦合；e2e 断言商家应收明细出现该单即可。

## 3. 数据模型（`packages/pickup-plugin/src/pickup-redemption.entity.ts`）

继承 core 基类（`id`/`createdAt`/`updatedAt`）。

| 列 | 类型 | 说明 |
|---|---|---|
| channelId | int NOT NULL | 渠道隔离（ChannelAware 铁律 + channels ManyToMany JoinTable） |
| orderId | int，`@Index unique` | 每单一条核销凭据（一生对一单） |
| code | varchar，`@Index unique` | 固定提货码（6 位字母数字，去易混淆字符），碰撞重试 |
| status | varchar default 'generated' | `generated→redeemed` 或 `generated→void` |
| claimedAt | datetime nullable | 核销时间 |
| claimedByUserId | int nullable | 核销人 User id（顾客/店员） |
| claimChannel | varchar nullable | `customer`（顾客自核销）/ `shop`（店员核销） |

- 日期列：`@Column({ nullable: true }) xxx?: Date`（阶段11 Date 铁律，不写死 timestamp/datetime）。
- 索引 `unique(orderId)` 保证幂等单记录；`unique(code)` 防码冲突。

## 4. 编排（PickupService）

### 4.1 取码（懒生成，幂等）
- `resolveMyPickupCode(ctx, orderId)`：加载订单 relations `['customer','customer.user']`，校验归属（`ctx.activeUserId === customer.user.id`）+ `deliveryType==='pickup'` + 已付款（状态 ≥ PaymentSettled）→ 查 PickupRedemption；无则生成唯一码（循环重试查重）并落库 `status='generated'`；有则直接返回（固定码，未核销不变）。

### 4.2 核销闸门（以 customer-shop 共用）
- 校验订单 `deliveryType==='pickup'`；校验存在 Shipped Fulfillment（备货完成）；取 PickupRedemption 且 `status==='generated'`；比对 `code`。任一不满足 → UserInputError，不产生半核销状态。

### 4.3 核销提交
- 置 `status='redeemed'` + `claimedAt` + `claimedByUserId` + `claimChannel` → 保存。
- 推进该订单所有 Shipped Fulfillment→Delivered（`orderService.transitionFulfillmentToState` 或逐单 `orderService.transitionOrderToState` 到 Delivered，以实现对齐阶段10 delivery 的推进手法为准）。
- 写 `order.customFields.pickupClaimed=true`（对齐前端徽标）。
- 订单 Delivered → 结算联动自动发生。

### 4.4 一次性防重
- 已 redeemed 码再次核销 → 拒绝（`UserInputError` 码已使用）。同一码并发核销由 `unique(orderId)` + status 校验双防。

### 4.5 取消作废
- 订阅 `OrderStateTransitionEvent`，订单进入 `Cancelled` → 其 PickupRedemption 若 `generated` 置 `void`。事件 order 不保证 relations 完整，按需 `OrderService.findOne` 重载（铁律）。

## 5. 权限与归属

- **顾客域（shop-api）**：`@Allow(Permission.Owner)` + `requireMyOrder`（`customer.user.id` 比对铁律）。
  - `myPickupCode(orderId)`：取本单提货码（含 code/orderCode/status/claimedAt）。
  - `claimMyPickup(orderId, code)`：顾客自核销。
- **店主域（admin-api）**：`@Allow(manageOwnShop.Permission)` + `requireMyShop`（复用 shop-plugin Shop，直接仓储避免 DI 环——阶段24手法）。
  - `myPickupOrders(options)`：本店待核销 pickup 订单清单。
  - `claimPickupByShop(code)`：店员凭顾客提货码核销，校验该单归属本店。
- **平台（admin-api）**：`@Allow(Permission.UpdateSettings)`。
  - `pickupRedemptions(options)`：全部核销凭据查询。

## 6. GraphQL 接口

**shop-api · 顾客侧（`@Allow(Permission.Owner)`）**
- `myPickupCode(orderId: ID!): PickupRedemption!`
- `claimMyPickup(orderId: ID!, code: String!): PickupRedemption!`

**admin-api · 店主侧（`@Allow(manageOwnShop.Permission)`）**
- `myPickupOrders(options): PickupRedemptionList!`
- `claimPickupByShop(code: String!): PickupRedemption!`

**admin-api · 平台侧（`@Allow(Permission.UpdateSettings)`）**
- `pickupRedemptions(options): PickupRedemptionList!`

**schema（共享类型）**
- `type PickupRedemption { id, orderId, code, orderCode, status, claimedAt, claimChannel }`
- `input ListOptions { skip, take }` / `PickupRedemptionList { items, totalItems }`
- 注意：`ListOptions` 若与 core 现有同名 input 冲突，沿用阶段25实证改名 `SubscriptionListOptions` 的思路，用 `PickupListOptions` 命名避免 schema 冲突。

## 7. 错误处理

- 非 pickup / 未付款 / 备货未完成 / redemption 不存在 / 已 redeemed / 已 void / 码不匹配 → 统一 `UserInputError`（中文场景可带 message）。
- 顾客查/核销他人单、店主核销非本店单 → `Forbidden`（归属前置校验）。
- 码生成冲突 → 循环重试取新码（有限次数，超限抛错）。
- 全部发生在单次写操作内，不产生半核销状态。

## 8. 测试（e2e，≥10）

复用各阶段骨架（`InventoryPlugin.init()` + `ShopPlugin.init({})` + `delivery-plugin` + `SettlementPlugin.init({ defaultCommissionRate: 0 })` + `PickupPlugin.init({})` + `singleStageRefundablePaymentMethod`）。覆盖：

1. 插件加载 + 建 pickup 订单付款 → `myPickupCode` 生成唯一码
2. 幂等：多次 `myPickupCode` 返回同一码
3. 未付款 / 非 pickup 订单取码被拒（UserInputError）
4. 备货完成前（未 Shipped）核销被拒
5. 备货完成（Shipped）后顾客自核销成功 → 码 redeemed + Fulfillment→Delivered
6. 一次性：核销后再次用同码 → 拒绝
7. 错误码 → 拒绝
8. 店员核销（本店 manageOwnShop，凭码）成功
9. 越权：非本人查码 / 非本店店员核销他人单 → Forbidden
10. 订单取消 → 未核销提货码作废（void）
11. 结算联动：核销后商家应收明细出现该单（阶段24）

## 9. 风险与前置依赖

- 依赖 delivery-plugin 已写入的 `Order.customFields.deliveryType`/`selectedPickupLocationId`（跨插件读，QueryBuilder 取 FK，避免 DI 环）。
- 依赖 `orderService` 推进 Fulfillment→Delivered（阶段10 手法）。
- 依赖阶段24 settlement-plugin 在订单达 Shipped/Delivered 自动入账（核销只是把订单推到位即联动）。
- 依赖 shop-plugin 店主账权 `requireMyShop` + `manageOwnShop`；店主下单归属用 `Order.customer.user.id` 比对。
- 不做真实硬件自提柜/门禁；顾客自核销即“凭码到点自助取货”的后端语义，前端扫码/输码实现不在本阶段。

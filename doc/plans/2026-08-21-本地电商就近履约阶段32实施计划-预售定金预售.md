## 0. 结论摘要

打通预售闭环，覆盖**定金预售 / 全款预售 / 预售价格分档**三模式，核心是**单订单两阶段支付**（自定义订单状态 `Deposited`）：

1. 自定义订单状态机：`declare module OrderStates { Deposited: never }` + `preSaleOrderProcess`（`ArrangingPayment→Deposited→PaymentSettled`），push 到 `config.orderOptions.process`
2. `PreSaleActivity` 实体（ChannelAware，`mode` deposit/full，`presalePrice` 价格分档，状态机 upcoming/active/delivered/ended）
3. `applyPreSale` 抢购一体：校验 → 限购 → 原子锁 `soldCount` → 写订单字段 → 动态打折到预售价
4. 两阶段支付 mutation：`payPreSaleFull`（一次收清）/ `payPreSaleDeposit`（收定金→Deposited）/ `payPreSaleTail`（收尾款→PaymentSettled），全部用 `PaymentService.createPayment` 指定金额，不走原生 addPaymentToOrder 全额剩余语义
5. `deliverPreSale` 到货 Release（active→delivered）
6. Promotion `pre_sale_discount` + `pre_sale_price` 动态取价
7. e2e 9 场景全链路

### Step 2: 实体 `pre-sale-activity.entity.ts`
```ts
import { Column, Entity, JoinTable, ManyToMany } from 'typeorm';
import { Channel, ChannelAware, DeepPartial, VendureEntity } from '@vendure/core';

export type PreSaleMode = 'deposit' | 'full';
export type PreSaleStatus = 'upcoming' | 'active' | 'delivered' | 'ended';

@Entity()
export class PreSaleActivity extends VendureEntity implements ChannelAware {
    constructor(input?: DeepPartial<PreSaleActivity>) { super(input); }

    @Column('varchar') name: string;
    @Column('varchar') mode: PreSaleMode;
    @Column() startAt: Date;
    @Column() endAt: Date;
    @Column({ nullable: true }) releaseAt?: Date;      // 到货/开售时间
    @Column({ nullable: true }) tailStartAt?: Date;     // 尾款窗口启
    @Column({ nullable: true }) tailEndAt?: Date;      // 尾款窗口止
    @Column('int') presalePrice: number;                 // 预售价(分)，0=不分档用原价
    @Column('int') depositAmount: number;                // 定金(分)，deposit 模式用
    @Column('int') totalStock: number;
    @Column('int', { default: 0 }) soldCount: number;
    @Column('int', { default: 1 }) limitPerUser: number;
    @Column('int') productId: number;
    @Column('int') variantId: number;
    @Column({ type: 'int' }) channelId: number;
    @Column('varchar', { default: 'upcoming' }) status: PreSaleStatus;
    /** 一次性由活动单位价格×件数折算（展示/计算钩子） */
    @ManyToMany(() => Channel)
    @JoinTable()
    channels: Channel[];
}
```
> ⚠️ 联合类型列（mode/status）显式 `@Column('varchar')`（阶段12/13/27 铁律，勿反射成 Object）。

```ts
declare module '@vendure/core' {
    interface OrderStates { Deposited: never; }

export const preSaleOrderProcess: OrderProcess<any> = {
    transitions: {
        ArrangingPayment: { to: ['AddingItems', 'Deposited', 'PaymentSettled', 'Cancelled'] },
        Deposited: { to: ['PaymentSettled', 'AddingItems', 'Cancelled'] },
    },
};
```

### Step 6: Promotion 条件/动作
**`pre-sale-promotion-condition.ts`**（`PriorityOrderCondition` / `order only`，仿 flash-sale）：
- `check`（async）：读 `order.customFields.preSaleActivityId` → runtime 查活动 → 校验存在、`status (active|delivered 均可打折到货前锁定价)`、窗口、`soldCount<totalStock`、订单含该变体 → 返回 `{ variantId, usePresale: true }`
- `priorityValue: 900`

**`pre-sale-price-action.ts`**（`PromotionItemAction`，`conditions` 含 condition）：
- execute：`const s = state.pre_sale_discount`；`!s?.usePresale` → 0
- `String(orderLine.productVariant?.id) !== s.variantId` → 0（对齐阶段14 类型坑）
- `presalePrice` 由 runtime 查活动得（condition 已把 `presalePrice` 放进 state）
- `unitPrice = pricesIncludeTax ? unitPriceWithTax : unitPrice`；`delta = unitPrice - presalePrice`；`delta>0 ? -delta : 0`

### Step 7: `pre-sale.service.ts`
- 注入 `TransactionalConnection`、`OrderService`、`PaymentService`；`init(injector)` 挂 runtime 连接
- `getActivity(ctx, id)`：`getRepository(ctx, PreSaleActivity).findOne({ where: { id, channelId } })`
- `requireCustomer(ctx)`：仿阶段31 review 口径（activeUserId 空→Unauthorized、无 customer→NotFound）
- `findActive(ctx)`：`status='active'` 列表
- `applyPreSale(ctx, activityId)`：
  1. requireCustomer；重载 order（含 lines.productVariant）
  2. 校验订单包含预售变体（变体 ID 类型统一 String 对比）
  3. 加载活动，校验 active + 窗口 + soldCount<totalStock
  4. 限购：该客户同活动非 Cancelled 订单数 ≥ limitPerUser → 抛 `Purchase limit exceeded`
  5. 原子锁：`qty` = 订单内预售变体行总件数；DB `UPDATE soldCount+=qty WHERE id=? AND soldCount+qty<=totalStock`，受影响=0 → 抛 `已售罄`（`UserInputError`）
  6. `orderService.updateCustomFields` 写 `{ preSaleActivityId, preSaleMode, preSaleDepositTotal, preSaleReleaseAt }` + `applyPriceAdjustments`
  7. `soldCount >= totalStock` → 置 `ended`
  8. 返回订单
- `payPreSaleFull(ctx, orderId)`：
  1. 重载 order；校验已绑活动 + `mode=full` + active 窗口
  2. 用 `PaymentService.createPayment(ctx, order, order.totalWithTax, method, {})` 创建 Settled 支付（method 复用 e2e/dummy）
  3. `.relation('payments').add(payment)` + `transitionToState('PaymentSettled')`
- `payPreSaleDeposit(ctx, orderId)`：
  1. 重载 order；校验状态 `ArrangingPayment` + `mode=deposit`
  2. 由活动 `depositAmount` 与订单内预售件数折算 `preSaleDepositTotal`（= depositAmount × 预售件数，或直接用 activity.depositAmount 一次性定金——**决策**：定金按「活动配置 depositAmount 一次」计，与件数解耦，避免多件时定金超半本就全款；e2e 用 depositAmount 直接作定金）
  3. `createPayment(order, preSaleDepositTotal)`（Settled）→ 关联 → `transitionToState('Deposited')`
  4. 写 `preSaleDepositTotal` 到 customFields（若尚未写）
- `payPreSaleTail(ctx, orderId)`：
  1. 重载 order；校验状态 `Deposited` + `mode=deposit` + 活动已到货（releaseAt≤now 或 `deliverPreSale` 已触发）
  2. 尾款窗口校验：tailEndAt 空，或 tailStartAt≤now≤tailEndAt
  3. `tailAmount = totalWithTax - 已付定金（本次前累计 Settled payments 金额）`
  4. `createPayment(order, tailAmount)`（Settled）→ 关联 → `transitionToState('PaymentSettled')`
- `deliverPreSale(ctx, activityId)`：校验 active → `status='delivered'`，`releaseAt` 落 now，若 deposit 模式把 `tailStartAt` 落到 `releaseAt`；返回更新
- `releaseStockForOrder(ctx, orderId)`：按订单内预售行件数回滚 `soldCount -= qty`（`WHERE soldCount - qty >= 0` 防负）；若活动在窗口内且 soldCount<totalStock 恢复 `active`（对齐秒杀 restoreActiveIfPossible）
- `findAll(ctx, options)` / `findOneById(ctx, id)`：admin 列表/详情

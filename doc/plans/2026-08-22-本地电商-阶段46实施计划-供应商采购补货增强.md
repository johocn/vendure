# 阶段46 实施计划：供应商采购补货（Supplier + PurchaseOrder）

> 目标：承接阶段44「后续方向5·商品维度库存盘点/调拨/供应商补货增强」，补齐仓库域缺的**供应商主数据 + 采购补货单**。
> 现状：`inventory-plugin` 已具备 `StockInOrder`(入库)/`StockOutOrder`(出库)/`StockMoveOrder`(调拨)/`StocktakeOrder`(盘点) 四类单据、`StockLedger`(供销存账本，bizType 已含 order/afterSales/stockIn/stockOut/stockMove/stocktake/manual)、就近库存 `variantNearbyStock`、分级权限(`ViewStock/ManageStockIn/Out/Move/Stocktake` + 角色绑定)、admin resolver + schema + e2e。**缺**：供应商档案、采购单、采购入库联动账本、后台管理页（inventory-plugin 目前无 dashboard）。
> 阶段45 已沉淀 dashboard `ListPage`/`defineDashboardExtension`/CSV 导出等后台扩展范式，本阶段复用。

## 1. 范围与验收

### A. 供应商档案（Supplier 主数据）
- 新实体 `Supplier`（ChannelAware，多店铺隔离）：`code/name/taxNumber/contactName/contactPhone/address/settlementDays(账期,天)/note` + `createdAt/updatedAt`。
- admin API：`Query.suppliers(options)/supplier(id)`、`Mutation.createSupplier/updateSupplier/deleteSupplier`（带唯一 code 校验、删除前置已有采购单禁止）。
- **验收**：新增/改/删供应商、按名称/税号分页列表、同 code 重复创建报错。

### B. 采购补货单（PurchaseOrder）标准生命周期
- 新实体 `PurchaseOrder` + `PurchaseOrderLine`：`code/state/supplierId/supplier/targetLocationId/note/staffId/orderDate/expectedArrivalDate/总投资额`、line 含 `productVariantId/quantity(订购量)/receivedQuantity(累计实收)/unitPrice/amount(=qty*price)`。
- 状态机：`Draft→Ordered→PartiallyReceived→Received→Completed`，`Draft/Ordered→Cancelled`。
  - `createPurchaseOrder`(Draft) → `placePurchaseOrder`(Ordered) → 可多次 `receivePurchaseOrder`（**分批到货**，累加 receivedQuantity；全部达成 → Received，部分达成 → PartiallyReceived）→ `completePurchaseOrder`(Received→Completed)。
  - 每次收货 `receivePurchaseOrder` 按实收增量对 `targetLocation` 调 `adjustStockForLocation`(+delta) 并写 **`purchase`** 账本（`bizCode=采购单号`）；单行超收/负数校验。
  - 取消：`Draft/Ordered` 态可取消；已收货(PartiallyReceived/Received)禁止取消。
- admin API：`Query.purchaseOrders(options)/purchaseOrder(id)`、`Mutation.createPurchaseOrder/placePurchaseOrder/receivePurchaseOrder/cancelPurchaseOrder/completePurchaseOrder`。
- **验收**：整单收货 → 目标仓库存增加 + `stockLedger(bizType=purchase)` 有记录；分批两次收货 → 中间态 PartiallyReceived、终态 Received；超收/二次堆叠拒绝；已收货禁止取消；Completed 后可再次下单不复用原单。

### C. 权限与角色绑定
- 新增 `ManagePurchase`(采购单管理)、`ManageSupplier`(供应商管理) 两个 `PermissionDefinition`；`inventoryPluginPermissions` 与 `ROLE_PERMISSIONS_MAP`（inventory-staff/manager/super-admin）补齐绑定；`super-admin` 带 SuperAdmin。
- **验收**：无 **ManagePurchase** 权限管理员调用采购 mutation 被拒；绑定角色后成功。

### D. 后台管理页（dashboard 扩展，复用阶段45 范式）
- 新增 `inventory-plugin/dashboard/`：`defineDashboardExtension({ routes:[supplierList, purchaseOrderList] })`；导航挂 `sales` 区。
  - `/suppliers`：供应商列表 + 新建/编辑/删除。
  - `/purchase-orders`：采购单列表（按状态筛选）+ 新建/下单/收货(分批录入)/完成/取消。
- **验收**：admin 页面能建供应商、建采购单、分批收货后库存与账本可见。

## 3. 非目标
- 不联动财务应付/结算（采购成本不落应付账；留后续）。
- 不做采购单与请购（PR）、质检拒收/退货给供应商流程。
- 不做供应商余额/采购金额统计报表。
- 不接真实 ERP/TMS 采购接口（纯 admin 录入 + 内部单据闭环）。

> 依赖就绪已验证：既有 `adjustStockForLocation`/`StockLedgerService` 为采购入库提供原子化`调库+账本`；dashboard `defineDashboardExtension`/`ListPage` 范式阶段45 已跑通；权限-角色绑定机制（`role-sync`+`ROLE_PERMISSIONS_MAP`）现成可扩展。

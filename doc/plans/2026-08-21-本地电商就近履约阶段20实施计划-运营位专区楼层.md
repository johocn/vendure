# 阶段20 · 实施计划（运营位/专区楼层）

依据：`2026-08-21-本地电商就近履约阶段20设计-运营位专区楼层.md`

核心：新插件 `operation-plugin`（`OperationSection` 专区 + `OperationItem` 条目），admin-api 配置运营位，shop-api 只读已启用专区及条目（banner 图 / 商品详情懒加载，防 N+1）。

## 执行顺序

### Step 1 — 插件骨架
- 新建 `packages/operation-plugin/`（tsconfig、tsconfig.build.json、package.json，peer `@vendure/core`，devDependencies 同 favorite-plugin；脚本 build/test/e2e）。
- `src/constants.ts`（loggerCtx、OPERATION_PLUGIN_OPTIONS）。

### Step 2 — 实体
- `src/operation-section.entity.ts`：`OperationSection`，列见设计；`code` unique；`@Index(['channelId','enabled','position'])`；`ChannelAware`（ManyToMany Channel + JoinTable）+ `channelId` 普通列 NOT NULL；`@OneToMany(() => OperationItem, i => i.section, { eager: true }) items`。
- `src/operation-item.entity.ts`：`OperationItem`，`sectionId` ManyToOne（`@Column({type:'int'}) sectionId` + `@ManyToOne(() => OperationSection, s => s.items)`），`type/sortOrder/title/imageAssetId/linkUrl/productId/channelId`。
- Date 列对齐阶段11铁律：不写死 `@Column type`，用 `createdAt/updatedAt` 由基类提供。

### Step 3 — 服务 operation.service.ts
- 注入 `TransactionalConnection`（`@vendure/core`）。
- `requireManager`：不依赖登录顾客（admin 走 Permission 守卫），服务只做数据访问。
- Admin：
  - `listSections(ctx)` / `getByCode(ctx, code)` / `create(ctx,input)` / `update(ctx,id,input)` / `delete(ctx,id)`。
  - `setOperationItems(ctx, sectionId, items)`：事务内 `repo.remove`（该 section 旧 items）+ 逐个 save 新 items（补 sortOrder/channelId/sectionId）。
- Shop：
  - `listEnabled(ctx)`：`find({ where: { channelId, enabled: true } })` order position DESC（items eager，按 sortOrder 升序）。
  - `getEnabledByCode(ctx, code)`：同 + code。
  - `resolveItems`：为条目批量解析 `imageUrl`（Asset.preview）与 `product`（core Product）——收集全部 id 一次性查询，Map 缓存防 N+1。

### Step 4 — 双 schema + resolver
- `src/operation-admin.resolver.ts`（admin-api）：Query `operationSections`/`operationSection(code)`；Mutation `createOperationSection`/`updateOperationSection`/`deleteOperationSection`/`setOperationItems`。全部 `@Allow(Permission.UpdateSettings)`。
- `src/operation-shop.resolver.ts`（shop-api）：Query `operationSections`/`operationSection(code)` 均 `@Allow(Permission.Public)`（只出 enabled）；`@ResolveField` body 解析 `imageUrl`/`product`。
- 类型/Input 在 `plugin.ts` 的 adminSchema/shopSchema 里定义（`OperationSection implements Node` 等）。

### Step 5 — plugin.ts
- `plugin.ts`：imports `PluginCommonModule`，entities `[OperationSection, OperationItem]`，providers `OperationService`，adminApiExtensions 挂 admin resolver，shopApiExtensions 挂 shop resolver；configuration 无 customFields 需并入（可用 mergeCustomFields 备用函数）。`OperationPlugin.init(options)` 静态工厂导出。

### Step 6 — package.json / 工作区
- 注册到根 `package.json` workspaces/依赖映射（`package-lock` 由 install/pnpm 更新）。本插件 peer 仅 core，无新增根依赖映射（如需要补 `@vendure/operation-plugin` paths）。

### Step 7 — e2e（≥8 用例）
- 复用 favorite 骨架：`createTestEnvironment`，plugins `[OperationPlugin.init()]` + ShopPlugin 骨架（提供可商品数据与 config）。
- 用例：
  1. admin 创建专区（含 items）成功，返回含 code/name/type/position/enabled
  2. admin 列出全部专区（含 items，按 position 排序）
  3. admin 按 code 查专区
  4. admin update 专区（改 name/position/enabled）
  5. admin setOperationItems 整段替换条目（id 变化、sortOrder 生效）
  6. admin delete 专区后查询消失
  7. code 唯一冲突（重复 code 建专区报错）
  8. shop 只读：只返回 enabled 专区、position 降序、items sortOrder 升序
  9. shop 未启用专区不返回；按 code 取未启用返回 null
  10. shop product 条目解析出 `product { id }`、banner 条目解析出 `imageUrl`
  11. 渠道隔离：另一 channel 看不到本 channel 专区
- 运行：插件目录内 `$env:PACKAGE='operation-plugin'; npx vitest run --config vitest.config.mts e2e/operation.e2e-spec.ts`；改实体后删 `e2e/__data__/*.sqlite`。

# 阶段18 · 店主自营后台账权体系 设计

> 承接：阶段17（商家店铺体系 shop-plugin）已落地 `Shop` 实体 + `Product.customFields.shopId`
> 目标：让店主拥有**自营后台账号**——开店审核通过后可开通店主管理员账号，登录后台仅能管理**自己店铺**范围内的店铺信息 / 商品 / 订单 / 评价，任何跨店铺或全局数据访问被拦截（账号+权限+归属三层闭环）。

## 1. 背景与现状

阶段17 的 `Shop` 是独立档案主体（复用 `ChannelAware`，定位轻量），`ownerId` 仅占位未打通账号；商品归属用 `Product.customFields.shopId`（int, public）。Vendure 原生已具备完整后台账号体系（`Administrator` + `Role` + 自定义权限），marketplace-plugin 的卖家即用「Administrator + 卖家 Role」承载。

本阶段把**「店主」落地为 Vendure 原生管理员**，打通：开店 → 开通店主账号 → 店主登录 → 自营管理 → 越权拦截。

## 2. 核心设计决策

### 2.1 店主账号模型：复用 admin API（店主 = Administrator）
- 店主是一个普通 `Administrator`：拥有**自定义权限 Role**（`ManageOwnShop`）+ 门店 Role 作用域，登录 admin API（Vendure 原生会话令牌/饼干）。
- 区别于 marketplace：marketplace 店是 **Channel**，靠 channel 作用域隔离；本方案 `Shop` 独立于 Channel，故**数据隔离一律按 shopId 语义**，不靠 channel 作用域。
- `Shop` 新增 `administratorId`（FK→Administrator，弥补 phase17 占位的 `ownerId`）。

### 2.2 自定义权限 `manageOwnShop`
- `manageOwnShop = new PermissionDefinition({ name: 'ManageOwnShop' })`。
- 注册于 `config.authOptions.customPermissions`（生成 Permission 枚举 + 可在 Role 上分配）。
- 所有店主自营 resolver 用 `@Allow(manageOwnShop.Permission)` 把关「是否为店主管理员」；再配合**归属校验**把关「是否本人店铺」。

### 2.3 归属解析：`ctx.activeUserId → Shop`
- `ctx.activeUserId` 是登录 **User** 主键。用 `Administrator.user.id === ctx.activeUserId` 反查 Administrator → `admin.id === Shop.administratorId` → 我的店铺。
- `requireMyShop(ctx)`：无店铺或店铺非 `active` 直接 Forbidden（**关闭店铺立即冻结店主后台**）。
- 归属解析**不依赖 `ctx.channelId`**（避免店主默认渠道与 channel 作用域耦合），一律以 `Shop.administratorId` 为准。

### 2.4 店主数据范围（全部按 shopId 隔离）
| 能力 | 结构 | 隔离口径 |
|---|---|---|
| 我的店铺 | `myShop` | `Shop.administratorId === myAdminId` |
| 店铺信息更新 | `updateMyShop` | 仅 name/description/logo/banner，禁改 slug/status |
| 商品管理 | `myShopProducts` / `addProductToMyShop` / `removeProductFromMyShop` / `updateMyShopProduct` | `Product.customFields.shopId === myShopId` |
| 订单查看 | `myShopOrders` / `myShopOrder` | 含我店商品行的订单；行投影为我店行（不泄露他人商品行） |
| 评价审核 | `myShopReviews` / `approveMerchantReview` / `rejectMerchantReview` | `Review.productId ∈ myShopProducts` |

### 2.5 店主订单投影（不暴露完整 Order）
- 通过 `OrderLine.productVariant.product.customFields.shopId === myShopId` 定位「我店行」，按订单聚合。
- 暴露 `MerchantOrder { orderId, code, state, totalWithTax, currencyCode, customerName, placedAt, items }`，其中 `items` 仅含我店商品行（不含他人店铺行），避免跨店数据泄露。
- e2e 规模用内存聚合（加载订单行+商品后 JS 过滤），标注为简化实现。

### 2.6 店主评价审核（跨插件，方向 shop-plugin → review-plugin）
- 评价审核落在 shop-plugin：店主 `myShopReviews` 列我店商品的评价，`approve/rejectMerchantReview` 审核。
- shop-plugin **import `Review` 实体**（peer dep `@vendure/review-plugin`），直查 `review` 表 + 自实现聚合重算（口径与 review-plugin 一致：approved 主评加权，`parentId IS NULL`）。
- 审核动作**先校验 `review.productId ∈ myShopProducts`** 再改状态，防止店主审核他人商品评价。
- 解耦边界：仅 import Review 实体类型与字段契约，不注入 ReviewService（避免跨插件 provider 导出/装配）；review-plugin 必须在应用同时加载（评价域本就依赖它）。

### 2.7 开店开通店主账号（平台侧 provision）
- admin-only mutation `provisionShopOwner(shopId, input{emailAddress,password,firstName,lastName})`：
  1. 幂等确保店主 Role 存在（`code: 'shop-owner'`，permissions: `[manageOwnShop.Permission]`，channels: 该店 channelId）。
  2. `administratorService.create` 建店主管理员 + 绑定该 Role。
  3. 写 `Shop.administratorId = admin.id`。
  4. 幂等：该店已有店主则返回已存在（或按需重绑）。
- 开店流程：admin `createShop`(applicant) → `setShopStatus(active)` → `provisionShopOwner` 开通账号。店主登录后进入自营。

### 2.8 关闭店铺冻结
- `setShopStatus(closed)` 后 `requireMyShop` 抛 Forbidden → 店主后台即时失效。
- 重新 `active` 即可恢复（幂等）。

## 3. 变更清单

### 3.1 shop.entity.ts
- `ownerId` → `administratorId`（`@Column int nullable`，FK 语义存 Administrator.id）。

### 3.2 shop.service.ts（新增店主域）
- `requireMyShop(ctx)` → Service。
- 平台侧：`provisionShopOwner` / `getShopByAdministrator`.
- 店主侧：`updateMyShop`(改名 update/updateOwnShop) / `getMyShopProducts` / `addProductToMyShop` / `removeProductFromMyShop` / `updateMyShopProduct` / `getMyShopOrders` / `getMyShopOrder` / `getMyShopReviews` / `approveMerchantReview` / `rejectMerchantReview`。
- 内部：`resolveMyShopFromActiveUser(ctx)`（Administrator.user.id→Shop）、`getMyShopProductIds`。

### 3.3 新增 merchant 类型 & schema（adminApiExtensions）
- `type CreateOwnerInput`、`type UpdateMyShopInput`、`type MerchantOrder`、`type MerchantOrderLine`、`type MerchantReview`。
- Query：`myShop: Shop!`、`myShopProducts(options: ShopListOptions): ProductList!`、`myShopOrder(orderId: ID!): MerchantOrder`、`myShopOrders: [MerchantOrder!]!`、`myShopReviews: [MerchantReview!]!`。
- Mutation：`provisionShopOwner(shopId: ID!, input: CreateOwnerInput!): Administrator`（平台）、`updateMyShop(input: UpdateMyShopInput!): Shop!`、`addProductToMyShop(productId: ID!): Boolean!`、`removeProductFromMyShop(productId: ID!): Boolean!`、`updateMyShopProduct(productId: ID!, input: UpdateMyShopProductInput!): Product!`、`approveMerchantReview(id: ID!): Boolean!`、`rejectMerchantReview(id: ID!): Boolean!`。

### 3.4 新建 merchant-resolver.ts（ADMIN API）
- 全部 `@Allow(manageOwnShop.Permission)`；`provisionShopOwner` 用 `Permission.UpdateSettings`（平台）。
- 各方法先 `requireMyShop(ctx)` 再按 shopId 操作。

### 3.5 plugin.ts
- `adminApiExtensions` 增 resolver；`configuration` 注册 `authOptions.customPermissions: [manageOwnShop]`。
- `imports` 本地 `mergePermissions`（幂等并入，避免重复注册）。

### 3.6 package.json
- 新增 peerDependency `"@vendure/review-plugin"`（仅 import `Review` 实体）。

## 4. e2e 用例

| # | 用例 | 断言要点 |
|---|---|---|
| 1 | 插件可加载；无店主管理员时 myShop 报 Forbidden | merchant 登入后 myShop 拒绝 |
| 2 | 开店+开通店主账号：admin createShop→active→provisionShopOwner | Administrator+Role 生成、shop.administratorId 绑定 |
| 3 | 店主登录自营：merchant 登录后 myShop 返回本人店铺 | myShop.name/slug 正确 |
| 4 | 店铺信息更新：updateMyShop 改 name/description 生效；禁改 slug/status 被拒 | 更新成功；改 slug 报错 |
| 5 | 商品管理：addProductToMyShop→myShopProducts 可见；updateMyShopProduct 改名生效；removeProductFromMyShop 移出 | 归属隔离 + CRUD 生效 |
| 6 | 订单查看：含我店商品行订单 myShopOrders 可见且 items 仅我店行 | 行投影不含他人店铺行 |
| 7 | 评价审核：myShopReviews 列我店商品评价；approve/reject 生效且只能审本店商品 | 审核成功；审他人商品评价被拒 |
| 8 | 越权隔离：店主 A 无法读店主 B 的店铺/商品/订单；访问全局 products 被 Forbidden | 403 / 空结果 |
| 9 | 关闭店铺冻结：closed 后 myShop 抛 Forbidden；重开恢复 | 冻结/恢复 |

## 5. 边界与简化
- 店主默认渠道/前台切换不做（归属用 administratorId，不依赖 channel 作用域）。
- 订单行投影做内存聚合（e2e 规模），生产可升级为 SQL 直查。
- 店主不开放库存/结算（留待后续）。
- 开店入驻的 C 端自助申请流程不在本阶段（本阶段开店为平台侧 createShop→provision）。

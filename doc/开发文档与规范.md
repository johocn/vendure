# Vendure 后端开发文档与规范

## 1. 技术架构

### 1.1 框架概述

本项目基于 **Vendure v3.6.4** 构建，Vendure 是一个基于 TypeScript 的开源电商框架，底层使用：

- **NestJS** — 模块化后端框架，依赖注入（DI）
- **TypeORM** — ORM 层，支持 PostgreSQL / MySQL / SQLite
- **GraphQL** — API 层，自动生成 Schema（Code-first + Schema-first 混合）

### 1.3 数据流架构

```
客户端 (H5/小程序/App)
    │
    ├── /shop-api (POST, GraphQL) ──→ ShopApiModule ──→ 业务 Service
    ├── /admin-api (POST, GraphQL) ──→ AdminApiModule ──→ 管理 Service
    └── /assets (GET) ──→ AssetServerPlugin
```

- **Shop API**（`/shop-api`）：面向 C 端用户，权限受控
- **Admin API**（`/admin-api`）：面向后台管理员，需 Admin 权限
- 两套 API 共享同一数据层（TypeORM Entity）

## 2. 插件架构

### 2.1 插件标准目录结构

```
packages/xxx-plugin/
├── src/
│   ├── plugin.ts                # @VendurePlugin 入口
│   ├── types.ts                 # Options 接口定义
│   ├── constants.ts             # DI token、logger 上下文
│   ├── xxx.entity.ts            # TypeORM Entity
│   ├── xxx.service.ts           # 业务逻辑层
│   ├── xxx-shop.resolver.ts     # Shop API GraphQL Resolver
│   ├── xxx-admin.resolver.ts    # Admin API GraphQL Resolver
│   └── xxx.controller.ts        # REST Controller（可选）
├── index.ts                     # 导出入口
├── package.json
├── tsconfig.json
└── tsconfig.build.json
```

### 2.2 Plugin 生命周期

```typescript
@VendurePlugin({
    imports: [PluginCommonModule],
    providers: [XxxService],
    configuration: config => {
        // 1. 注册认证策略
        // 2. 扩展 CustomFields
        // 3. 注册 PaymentMethodHandler
        // 4. 注册 PromotionAction/Condition
        return config;
    },
    shopApiExtensions: {
        schema: () => gql`...`,
        resolvers: [XxxShopResolver],
    },
    adminApiExtensions: {
        schema: () => gql`...`,
        resolvers: [XxxAdminResolver],
    },
    compatibility: '^3.0.0',
})
export class XxxPlugin {
    private static options: XxxPluginOptions;
    constructor(@Inject(XXX_OPTIONS) private options: XxxPluginOptions) {}
    static init(options: XxxPluginOptions): Type<XxxPlugin> {
        XxxPlugin.options = options;
        return XxxPlugin;
    }
}
```

### 2.3 编译规范

**重要**：插件编译必须使用 `npm run build`，不能使用 `npx tsc`。

```bash
cd packages/xxx-plugin
npm run build   # 等价于: rimraf lib && tsc -p ./tsconfig.build.json
```

- 编译输出到 `lib/` 目录
- `tsconfig.build.json` 配置了 `outDir: "./lib"` 和 `declaration: true`
- 编译后 `lib/src/` 下生成 `.js` + `.d.ts` + `.js.map`

## 3. 认证体系

### 3.1 AuthenticationStrategy 接口

Vendure 认证策略需实现 `AuthenticationStrategy<T>` 接口：

```typescript
interface AuthenticationStrategy<T> {
    readonly name: string;
    init(injector: Injector): Promise<void>;
    defineInputType(): DocumentNode;     // GraphQL Input 类型
    authenticate(ctx: RequestContext, data: T): Promise<User | false | string>;
}
```

### 3.2 认证方式对比

| 方式 | 策略名 | Input 字段 | 插件 | 用户标识 |
|------|--------|-----------|------|---------|
| 手机验证码 | `phone` | `phoneNumber` + `code` | phone-auth-plugin | 手机号 |
| 微信 H5 | `wechat` | `code` + `type:"mp"` | wechat-auth-plugin | `wechat_mp_{openid}` |
| 微信小程序 | `wechat` | `code` + `type:"mini"` | wechat-auth-plugin | `wechat_mini_{openid}` |
| 账号密码 | 内置 | `username` + `password` | Vendure 核心 | identifier |

### 3.3 Token 机制

- Vendure 认证成功后，Token 通过 **HTTP Response Header** `vendure-auth-token` 返回
- **不在** GraphQL response body 中
- 前端需从 `uni.request` 的 `res.header` 中提取
- 后续请求通过 `Authorization: Bearer {token}` 传递

## 4. 数据库规范

### 4.1 Entity 定义

```typescript
@Entity('xxx_table')
export class XxxEntity extends VendureEntity {
    @Column()
    name: string;

    @Column({ type: 'int', default: 0 })
    amount: number;

    @ManyToOne(type => Customer)
    customer: Customer;
}
```

### 4.2 CustomFields 扩展

```typescript
// 在 plugin.ts 的 configuration 中注册
config.customFields = {
    ...config.customFields,
    Customer: [
        { name: 'wechatOpenid', type: 'string', nullable: true },
        { name: 'wechatMiniOpenid', type: 'string', nullable: true },
    ],
};
```

### 4.3 PostgreSQL 注意事项

- 数值类型建议显式声明 `{ type: 'int' }` 或 `{ type: 'decimal' }`
- 布尔字段使用 `{ type: 'boolean', default: false }`
- JSON 字段使用 `{ type: 'simple-json', nullable: true }`
- 开发环境使用 `synchronize: true`，生产环境使用 migrations

## 5. GraphQL API 设计规范

### 5.1 Shop API vs Admin API

| 特性 | Shop API | Admin API |
|------|----------|-----------|
| 路径 | `/shop-api` | `/admin-api` |
| 权限 | 公开 + 认证用户 | 管理员角色 |
| 注册方式 | `shopApiExtensions` | `adminApiExtensions` |
| 典型用途 | 商品浏览、购物车、下单 | 商品管理、订单处理 |

### 5.2 Schema 扩展

```typescript
shopApiExtensions: {
    schema: () => gql`
        type XxxResult {
            id: ID!
            name: String!
        }
        extend type Query {
            getXxx(id: ID!): XxxResult!
        }
        extend type Mutation {
            createXxx(input: XxxInput!): XxxResult!
        }
        input XxxInput {
            name: String!
        }
    `,
    resolvers: [XxxShopResolver],
}
```

### 5.3 Resolver 模式

```typescript
@Resolver()
export class XxxShopResolver {
    constructor(private xxxService: XxxService) {}

    @Query()
    async getXxx(@Args('id') id: string) {
        return this.xxxService.findOne(id);
    }

    @Mutation()
    async createXxx(@Args('input') input: any) {
        return this.xxxService.create(input);
    }
}
```

## 7. 编码规范

### 7.1 命名约定

| 类型 | 规范 | 示例 |
|------|------|------|
| 文件名 | kebab-case | `wechat-auth.service.ts` |
| 类名 | PascalCase | `WechatAuthService` |
| GraphQL Type | PascalCase | `JsapiSignature` |
| GraphQL Query/Mutation | camelCase | `wechatJsapiSignature` |
| 常量 | UPPER_SNAKE_CASE | `WECHAT_AUTH_PLUGIN_OPTIONS` |
| DI Token | UPPER_SNAKE_CASE Symbol | `WECHAT_AUTH_PLUGIN_OPTIONS` |
| 环境变量 | UPPER_SNAKE_CASE | `WECHAT_AUTH_APP_ID` |

### 7.2 错误处理

```typescript
import { Logger } from '@vendure/core';
import { loggerCtx } from './constants';

try {
    // 业务逻辑
} catch (e: any) {
    Logger.error(`操作失败: ${e.message}`, loggerCtx);
    throw new Error('操作失败');
}
```

- 使用 Vendure 的 `Logger` 而非 `console.log`
- 每个插件定义 `loggerCtx` 常量用于日志标识

### 7.3 环境变量

- 敏感配置（密钥、Token）必须通过 `process.env` 注入
- 使用 `??` 提供默认值，`||` 处理空字符串
- 开发环境使用 `dev-config.ts` 中的 dev bypass 模式

## 8. 开发工作流

### 8.1 新建插件步骤

1. 创建目录 `packages/xxx-plugin/src/`
2. 编写 `types.ts`（Options 接口）
3. 编写 `constants.ts`（DI token + loggerCtx）
4. 编写 `plugin.ts`（@VendurePlugin 装饰器）
5. 编写 Entity / Service / Resolver
6. 编写 `index.ts` 导出
7. 编写 `package.json`（name: `@vendure/xxx-plugin`）
8. 编写 `tsconfig.json` + `tsconfig.build.json`
9. 编译：`cd packages/xxx-plugin && npm run build`
10. 在 `dev-config.ts` 中导入并注册

### 8.2 dev-config.ts 插件注册

```typescript
// 条件加载模式（需要环境变量才启用）
...(process.env.XXX_CONFIG ? [XxxPlugin.init({
    key: process.env.XXX_CONFIG,
})] : []),

// 无条件加载
XxxPlugin.init({ defaultOption: 30 }),
```

### 8.3 开发循环

```bash
# 1. 修改插件源码
# 2. 编译插件
cd packages/xxx-plugin && npm run build

# 3. 重启 dev-server
cd packages/dev-server && npm run dev:server

# 4. 验证（GraphiQL）
# http://localhost:3000/graphiql/shop
```

### 8.4 dev bypass 模式

部分插件在开发环境支持 bypass 模式，无需真实第三方服务：

| 环境变量 | 插件 | 效果 |
|---------|------|------|
| `DEV_BYPASS_SMS=true` | phone-auth-plugin | 验证码固定为 123456，不调用阿里云短信 |
| `DEV_BYPASS_WECHAT=true` | wechat-auth-plugin | 使用测试 AppID，微信认证返回测试用户 |
